# v0.0.4 复现入口

在仓库根目录运行。沿用 `.venv-cached` 模型环境及 `.venv-eval` 数据／评测环境。大型数据和权重位于 artifacts，不入库；GPU 范围按当前授权选择。

## 数据

```bash
CUDA_VISIBLE_DEVICES='' .venv-eval/bin/python scripts/download_training_corpus.py
CUDA_VISIBLE_DEVICES='' PYTHONPATH=src .venv-cached/bin/python scripts/prepare_training_tokens.py
CUDA_VISIBLE_DEVICES='' PYTHONPATH=src .venv-eval/bin/python scripts/prepare_full_eval.py
```

训练数据来自固定 no_robots snapshot（CC-BY-NC-4.0），仅做英语指令训练稳定性诊断，不代表最终蒸馏配方。最后 assistant 回答才有 CE／KL targets；切块处不计算跨块 target，packing 不跨文档 attention。保留初始 prompt 去重、过滤计数、文件及 template 哈希。开发 pilot 用于路由稳定性判断，不读取 benchmark 分数选 checkpoint。

## 训练与恢复

```bash
CUDA_VISIBLE_DEVICES=0,1 PYTHONPATH=src .venv-cached/bin/torchrun \
  --standalone --nproc_per_node=2 -m rmt.train --config configs/train/tiny.yaml
CUDA_VISIBLE_DEVICES=0,1 PYTHONPATH=src .venv-cached/bin/torchrun \
  --standalone --nproc_per_node=2 -m rmt.train --config configs/train/tiny.yaml --verify-resume

PYTHONPATH=src .venv-cached/bin/python scripts/run_training_stage.py \
  --gpus 0,1,2,3 --verify-restart --configs configs/train/fixed_128.yaml configs/train/opened_128.yaml
CUDA_VISIBLE_DEVICES=0 PYTHONPATH=src .venv-cached/bin/python scripts/validate_training_export.py \
  artifacts/v0.0.4/train/fixed_128_deterministic
.venv-cached/bin/python scripts/summarize_training_stage.py
```

已有完成报告的目录拒绝直接覆盖；重做实验需配置新的 artifact_dir／report。`--resume` 从已保存的优化步边界继续，`--verify-resume` 则执行保存后的一个参考步并核对 loss 与参数 SHA256。精确恢复要求 config／数据／world size／实现／环境一致，不支持通过修改 steps 偷换日程。`save_every` 可启用周期保存。

默认显式启用确定性算法和 CUBLAS workspace（用于逐字节恢复）；全参数 FP32 master、BF16 计算、root FSDP2、重计算、精确 teacher KL；编译由 config 显式开启，失败不静默降级。全局梯度范数按分片求和裁剪。固定路由与 learned 使用相同数据顺序、步数和损失；相同 tokens 并不意味着相同 GPU-hours。报告热步与完整任务耗时，不按卡数线性外推。

导出的 `hf/` 保存最终 routing_mode 与 prior；DCP 保存 optimizer／scheduler／RNG／cursor／数据和源码身份。HF 导出在 replay 检查前完成，不包含用于验证恢复的额外一步。

## 完整基线评测

先按 v0.0.3 使用说明启动原生 Qwen 服务，输出上限 32768 时设置 `--max-context 40960`；HTTP client timeout 为 7200 秒，不自动重试长生成。

```bash
CUDA_VISIBLE_DEVICES='' PYTHONPATH=src .venv-eval/bin/python -m rmt.evaluation.run \
  --model qwen --port 9007 --benchmark math_500 --phase full \
  --data-root artifacts/v0.0.4/datasets --output-root artifacts/v0.0.4/eval \
  --config configs/eval/v004_full_non_thinking.json

# 可选：两个相同元数据的服务副本，在统一入口分担长请求。
CUDA_VISIBLE_DEVICES='' .venv-eval/bin/python scripts/serve_eval_pool.py --ports 9004,9005 --port 9010
# 将上面的 benchmark 换为 ifeval、port 换为 9010。
```

保持原生 Qwen 对应的 attention 选项并记录差异；最终完整基线均为 HF SDPA；原数学 eager 的未完成尝试保留但不纳入评分。数学使用四副本、IFEval 使用两副本。proxy 仅转发 loopback chat 请求，先验证两个模型服务元数据相同，不修改 prompt 或 scorer。

最终汇总需明确传入两个已完成 work 目录，不能自动挑选最后创建但未完成的目录：

```bash
CUDA_VISIBLE_DEVICES='' PYTHONPATH=src .venv-eval/bin/python scripts/summarize_full_baseline.py \
  --ifeval PATH_TO_COMPLETED_IFEVAL_RUN --math PATH_TO_COMPLETED_MATH_RUN
```

LCB 的旧 test5 子集实际截止 2025-01-04；已标记覆盖偏差。本轮先审计，不将 32 题子集当作完整论文 v5 结果。
