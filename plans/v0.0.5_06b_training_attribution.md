# v0.0.5：Qwen3-0.6B 训练归因、规模扩展与动态循环验证

日期：2026-10-08。状态：用户已授权实施；进度和验证以过程记录为准。

用户已确认按“先归因 → 选择训练目标 → 扩大训练 → 验证动态深度收益”推进，并将实验基座从 Qwen3-4B 改为 Qwen3-0.6B，以降低资源成本。本文中的具体预算、深度和门槛是实施默认方案；不把历史 4B 实验结论直接迁移到 0.6B。

过程记录：`plans/v0.0.5_06b_training_attribution_record.md`；实施开始时创建，持续记录问题、决策、命令、产物、成本、失败与结论，并按可 review 的工作单元提交代码。

## 1. 本轮目标和边界

1. 验证未经训练的 0.6B RMT 原层序路径与原生模型一致，并定位训练造成的质量变化。
2. 在小规模受控实验中选择答案 CE 与基座 KL 的配方，再增加训练 token 数。
3. 分别检验额外循环与按内容动态退出的价值，报告质量、计算量、吞吐和显存。
4. 保留整套绑定专家、逐 token 固定退出规则、KV cache、HF checkpoint、packing、compile、重计算与多卡能力。
5. 暂缓投影解绑、可学习退出器、前段自由路由和新增复杂路由算法；不把多个结构变化同时放入主实验。
6. 新实验不训练或加载 4B 作为在线教师。旧 4B 结果只作离线历史审计，不重新跑完整 4B 实验。

目标是得到可信的正面或负面实验结果，不以“必须超过原生模型”作为工程完成条件。工程通过、质量恢复、额外深度收益、动态分配收益分别验收。

## 2. 模型迁移与循环预算

基座使用官方 `Qwen/Qwen3-0.6B`，不是 Base 版本。官方配置：28 层，hidden size 1024，FFN intermediate size 3072，16 个 Q heads、8 个 KV heads，head_dim 128，词表 151936，embedding 与 LM head 共享权重。

来源：[官方配置](https://huggingface.co/Qwen/Qwen3-0.6B/blob/main/config.json)、[模型卡](https://huggingface.co/Qwen/Qwen3-0.6B)。实施时将 main 解析成不可变 revision，记录所有配置、tokenizer、模板及权重指纹。当前已检查的 `/share/project/eai_pwm/models/Qwen` 目录没有 0.6B；预定下载目录 `/share/project/eai_pwm/models/Qwen/Qwen3-0.6B`，不能将它写成已就绪。

| 项目 | v0.0.5 默认值 | 说明 |
| --- | --- | --- |
| 绑定专家数 | 28 | 对应原始 28 层，一层一套权重 |
| 原层序基线 | fixed28 | 前 28 次严格按原始专家顺序 |
| 额外深度对照 | fixed32 | 比原层数增加 4 次，约 14.3% cell 次数 |
| 动态预算 | 均值 32，校准区间 [31,33] | 不是实际 FLOPs 或耗时预算的替代 |
| 最小／最大深度 | 28／36 | fixed36 仅作触顶及质量诊断 |
| 退出策略 | H、P 小规模诊断；H+P 主候选 | 保留固定规则，全部重新校准 |
| 追加专家路径 | 先比较尾部 8 套与从头循环 | 尾部为专家 20–27；选定后主实验统一 |

不机械沿用 36／40／48 或原阈值。H+P 的检查窗口、连续满足次数与首次合法退出深度必须显式测试，避免组合判据的等待机制把所有 token 被动锁在 32 次。

参数验收用实际加载模型的唯一参数统计，单列 embedding、专家、norm、router 和可训练参数；不重复计算 tied weights。若沿用当前 router，新增参数为 `28×1024 + 36×28 = 29,680`。固定与动态对照使用相同最大深度配置，避免容量不同。此数是配置推导，实际报告以实测为准。

特别检查 Q 投影输出维度：`16×128=2048`，并不等于 hidden size 1024；不能根据 hidden size 反推 head_dim。检查模型转换、tied embedding 导出／重载、FSDP 分片和优化器是否保持共享语义。清理实验入口中硬编码 36、2560、4B 路径，保留旧配置兼容性。

## 3. 历史证据及归因边界

旧最终模型训练路径为 32 步 warmup 后接 64 步教师答案训练；约 451,662 个输入 token、370,176 个监督 token。初期原始答案动态对照是独立分支，没有累加进最终模型。

旧 32B 数据共接受 804 条，但每个最终分支实际只见到 395 个唯一来源 ID、335,019 个监督 token。旧损失为 32B 离线答案 CE 加 0.5 倍原生 4B 在线 KL，不能称为 32B logits 蒸馏。

旧 IFEval 下滑和动态退出集中于 40 次都是待解释现象。新基座可以验证是否出现相似问题，但不能单凭新实验宣布已经解释旧 4B 退化。旧记录／响应／曝光统计用于离线核查；无法解释的部分明确保留。

## 4. P0：正确性、数据监督和评测基线

### 4.1 原生与未训练 RMT

- 使用同一 0.6B 权重、tokenizer、non-thinking 模板、generation config、dtype、attention backend 和输入，比较原生 Transformers 与未训练 fixed28。
- 严格 eager 路径在固定软件／硬件／batch 条件下要求 logits bitwise 相同；比较 prefill、逐 token decode、cache/no-cache、左右 padding、不同长度和 HF 保存重载。跨 backend 或 batch 形状不承诺 bitwise。
- 默认 compile 性能路径单列误差、greedy token 分歧与评测质量；记录实际编译覆盖、graph breaks、编译成本和稳态吞吐。
- 核查 EOS、模板中的 non-thinking 标记、answer 提取和截断。终止 token 从当前基座读取，禁止复制旧模型常量。
- 严格路径不通过时停在正确性阶段，不通过训练弥补实现差异。

### 4.2 训练数据与 loss 审计

- 展示可读的 token／label 样例，核验 assistant-only mask、shift、EOS、padding、pack 边界及跨文档 attention 隔离。
- 比较同一数据独立执行与 packing 的 loss／梯度；支持 token 归一化的全局 CE/KL，避免不同 rank 监督长度造成权重偏差。
- `kd_weight=0` 时不得加载或运行在线教师；generation metadata 从基座独立加载，不能依赖教师对象完成导出。
- 在线 KL 如启用，教师为冻结的原生 Qwen3-0.6B，固定原层序；检查 tokenizer 对齐、KL 方向、温度和掩码，并写入 manifest。
- 从原始映射权重开始建立短训曲线；取消默认复用旧 no_robots warmup。需要深度预热时必须成为可见的配对实验因素。

### 4.3 基线与评测隔离

建立 0.6B 原生、未训练 fixed28、后续短训 checkpoint 的独立结果。沿用已有官方评测工具和已审计的 adapter，主终测为 IFEval strict prompt accuracy 与 MATH-500 accuracy。

开发选模使用独立指令遵循／数学开发数据和分领域 CE，不拿两项正式测试集反复选 loss、checkpoint 或阈值。正式基线可先运行；训练方案冻结后才执行候选正式测试。新的 0.6B 分数不能与旧 4B 表直接作为架构收益比较。

## 5. P1：低成本选择训练目标

先在固定28原层序、同初始化、同数据顺序、同监督 token 数上比较三个配方：

| 配方 | 损失 | 在线教师 |
| --- | --- | --- |
| A | 答案 CE | 无 |
| B | CE + 0.1×KL | 冻结原生 0.6B |
| C | CE + 0.5×KL | 冻结原生 0.6B |

KL 采用当前已验证实现，显式记录方向／温度；以上权重是候选，不默认旧 0.5 最优。离线答案可以来自 32B，在线 KL 教师始终另列。

首轮每组最多 100 万监督 token，在 0、25万、50万、100万处记录开发曲线。初始化、优化器、学习率、样本顺序相同，只改变 KL 权重。初始主学习率 1e-5；若三组都未出现有效学习，再单独比较 3e-5，禁止同时大范围扫描学习率与 KD。非有限 loss／梯度或持续明显退化时提前停止并留存失败。

选模顺序：指令遵循开发集无超过 2 个百分点的下降、数学开发集无超过 2 个百分点的下降，再比较领域平衡 CE 与实际成本。该阈值是工程筛选门槛，不是统计非劣证明；同时给样本量与置信区间。若全部失败，先检查数据配比／监督／学习率，不进入大规模训练。相近方案优先无在线教师的 CE，以节约计算。

获选配方用于后续训练；P1 的训练后权重默认不作为 P2 初始化，以免试验累计训练量不清。

## 6. 数据准备与更强教师

沿用可追溯公开来源：UltraChat 通用指令、OpenR1-Math、OpenCoder 代码及其中文子集。中文历史实际来源是 OpenCoder 的 filtered_infinity_instruct，不能写成已下载原始 Infinity-Instruct Gen。每个来源记录精确 revision、许可、抽样规则和清洗计数。

1. 按规范化 prompt／近重复组先划分 train、halt_calibration、dev、test，再生成教师答案；沿用旧数据时核对所有 split 与 benchmark 排除清单。
2. 旧 804 条 32B 答案可用于 P1，重新按 0.6B tokenizer 统计和审计；禁止沿用旧 token 缓存。验证难度与学生开发损失分布，不默认更强教师答案一定易学。
3. P2 目标为 1万～2万条合格答案。先额外生成 1,000 条测量接受率、监督 token 和 GPU-hours，再分批扩充；1万～2万是合格数量目标，不是生成请求数量或训练曝光量。
4. 教师沿用 Qwen3-32B 离线 non-thinking，优先复用已有合格产物；本版不运行 32B 在线 logits 蒸馏。若生成成本超预算，使用已有答案与公开源答案扩大覆盖，明确记录配比，不能静默改用另一个教师。
5. 初始按监督 token 规划通用／指令遵循 50%、数学 25%、代码 15%、中文通用 10%；分桶互斥，中文优先归类。按独立开发集决定是否调整，冻结后主实验保持一致。
6. 完整保留答案结束标记。拒绝截断答案、空答案、明显格式错误；数学执行答案验证；代码至少语法检查，有可用测试时记录执行结果。语法通过不代表正确，不能据此宣称所有教师答案已验证。
7. 如需补充格式约束训练，使用独立模板／内容，标记合成来源；不得复制 IFEval 题目。去污染包括规范化精确匹配、包含和近重复筛查，明确无法排除教师预训练污染。

先报告清洗后的唯一条数和可用监督 token，再决定重复轮次。1,000 万 token 训练预算不等于 1,000 万唯一 token；3,000 万可能包含多轮，必须报告 unique IDs、重复次数和累计曝光。若数据不足，不能通过隐式过采样声称完成数据扩展。

## 7. P2：扩大训练与深度对照

主预算每分支累计 1,000 万监督 token；仅当学习曲线、质量和预算支持时继续到累计 3,000 万，而非额外再训 3,000 万。序列长度先固定 2048，统一完整样本保留／长度筛选策略。保存 100万、300万、1000万及扩展阶段检查点，按真实 target 数停止并记录最后一步超出量。

### 7.1 先隔离额外深度

- 从同一个未经训练的 0.6B 映射 checkpoint 开始训练 fixed28 与 fixed32。
- 前 28 次保持原层序；用小型固定预算开发诊断选择追加路径，主对照全程固定该路径，不同时学习 router。
- 相同数据顺序、loss、初始化、监督 token、学习率日程；比较 fixed32 相对 fixed28 的质量变化。
- 原生未训练 0.6B 是实际使用基线；训练后 fixed28 是数据／SFT 对照。不能把 fixed32 对未训练原生的提升全部归因于循环。

### 7.2 再隔离动态退出

从 fixed32 的同一个预定检查点分叉两个分支：继续 fixed32 与 H+P，按相同数据、token 预算继续训练。分叉点默认累计 100 万监督 token，计入每个分支的累计预算；fixed28 单独从原始权重按同总量训练。

H、P 先作小规模校准／成本诊断，不默认各运行完整 1,000 万 token。H+P 的阈值只使用 halt_calibration；开发质量用于预先限定的候选选择，正式测试不可参与。prefill／decode 深度分别校准和报告，平均预算达不到时报告失败。

主实验默认不加入独有的强制最大深度课程。若深层训练不足、需要 10% fixed36 批次，则 fixed32 分叉对照同样应用该日程，并命名为 anchor32；额外保留少量纯 fixed32 诊断，准确区分训练与推理深度。

对相同 checkpoint 交叉评测 fixed28／fixed32／H+P，仅用于解释训练与推理深度；不能与独立训练分支混为一张无标识结果表。

追加段 learned routing 后置为条件实验：仅在固定路径稳定、深度对照已有解释后开放，并增加同日程固定路径对照。报告原先验偏离率、专家占用及代价；不要求本轮一定完成路由收益验证。

## 8. 性能、资源和公平性

最新资源约束为仅物理 GPU 4–7，共 4×H100。0.6B 不默认每个分支占满 4 卡：先测 1／2 卡，以及有必要时 4 卡，选择实际监督 token/s 与 GPU-hours 更合适的布局。保留 FSDP2 可用性，比较小模型复制训练与分片通信开销；独立任务只能使用不重叠设备。

测量包括真实 2048 长度与代表性动态分布、compile 冷启动／稳态、验证、保存、恢复、teacher forward 和数据处理。正式预算使用端到端速度，不用极短 smoke 推算。梯度累积、有效 batch 和全局 token loss 口径固定。

本轮建议资源上限 96 GPU-hours（4卡×24h），包含新教师生成、训练、评测和必要复验；不是每阶段分别 24h。初始分配上限：正确性／短训 12、教师生成 16、主训练 48、评测／复验 20 GPU-hours。可按实测调整分项，但不得静默突破总额。下载等待单列墙钟时间，不计作 GPU 忙时；同时报告任务设备预留时间，避免掩盖资源占用。

超过预算预估时，依次取消 3,000 万扩展、后置路由和完整 H/P 训练，优先保留正确性、fixed28／fixed32 配对及动态小规模归因。仍不足时减少所有主分支的共同 token 预算，冻结并记录新预算，不保留不等训练量却称公平对照。

报告两种口径：相同监督 token 的质量变化，以及相同 GPU-hours／估算 FLOPs 的质量曲线。后者必须有对应预算 checkpoint，不用 cell 次数替代实测。教师生成成本单列总成本和共享摊销；额外 LM head 检查、路由、KV 搬运均计入动态推理代价。

推理测 batch 1／4／8、短／长 prompt、固定生成长度和实际 EOS 场景，报告 prefill 延迟、decode tokens/s、峰值显存和冷启动。原生高性能服务可用 vLLM；数值等价检查用同 backend Transformers。跨框架速度结果必须标注，不作为单独的架构效率证据。

## 9. 评测与结论标准

- 开发阶段按领域记录 CE、指令遵循、数学答案正确率、长度、重复率、截断率、EOS 行为；跟踪训练／开发差距。
- 正式评测冻结 checkpoint、模板、采样参数、seed、adapter、数据版本和 halting 配置，运行完整 IFEval／MATH-500。保留逐题响应，使用已有可靠恢复机制，禁止跨模型或协议复用缓存。
- 相对原生与 fixed28／fixed32 分别报告差值、配对 bootstrap 95% 区间；首轮一个训练 seed 只作探索，有候选收益再补第二个训练 seed。题目重采样区间不替代训练 seed 方差。
- 深度报告 mean、P50／P90／P99、直方图、触顶率及分任务／长度分布。若超过 95% token 停在同一步，标记动态行为退化，不能宣称内容自适应收益。
- 与 fixed32 质量接近但速度更慢，只能说明策略可运行；深度降低却实际计算未降低，不能宣称效率收益。
- 若结果在统计和训练方差范围内不确定，结论写“未证明收益”；数据规模扩大仍无改善时保留负面结果，不以继续扩充掩盖问题。
