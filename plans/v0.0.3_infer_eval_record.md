# v0.0.3 推理与评测实施记录

## 开始与范围变更

- 用户要求启用 KV cache，固定循环数允许按 recurrence 建独立缓存；默认编译＋cached 推理，保留严格参考路径。
- 目前授权 GPU 0–7。按性能 pilot 自主选择保守的正式回归规模，所有决策记录，不执行需要付费 judge 的任务。
- 不改动用户正在进行的 v0.0.2 record 文件搬迁；本次提交只包含本任务文件。
- 性能门槛按 plan 的 1.10× 冻结；先测同缓存策略的 eager/compile，不用缓存带来的收益冒充 compile 加速。

## I1 初步实现

- 新增预分配 recurrence cache，写入只追加；返回有效前缀以复用既有因果 mask。暂不把可变 cache mutation 捕获进编译图，编译投影函数以减少不必要重编译。
- 新增离线 runner、逐请求独立采样 RNG 和 OpenAI-compatible 本地微批服务；默认 cached／compiled，Qwen reference 使用 HF DynamicCache。
- 17 项单测通过，包括混合路由的 capacity cache、重排、溢出和采样策略。
- 真实 4B 编译数值和热运行对照已启动。EvalScope 使用独立 Python 3.12 环境，先选与已核对接口匹配的 1.0.0；自动依赖解析耗时过长，改为先安装主包再核对依赖，避免牵动现有模型环境。

## I2 第一轮真实模型结果

- 默认 Inductor BF16 融合误差超过原门槛（relative RMSE≈0.0221、ΔNLL≈0.0109），报告保存在 `performance_initial_failed.json`。
- 查阅本机 torch 配置后，启用 `emulate_precision_casts=True` 保留 eager 中间舍入。重跑同一真实 4B：logits 差异与 ΔNLL 均为 0，greedy 序列一致；单请求约 1.145×、batch 4 约 1.105×。继续扩展长度矩阵和混合路由，不用该短样例代替全部性能验收。
- GPU 0／1 分别运行长输入矩阵及混合路由对照；GPU 2／3 启动 RMT／Qwen 本地服务。
- 网络探针显示直连和两个备用代理不可用或超时，默认认证代理可下载 EvalScope。只记录代理类别，不存凭据。

## I2 扩展与 I3 接入

- 严格参考新增真实 BF16、两条不同长度 prompt、prefill＋4 个 decode step 的逐字节检查：Qwen DynamicCache 与 RMT capacity cache logits 全部一致，tokenizer 输入一致，见 `reference_bitwise.json`。这是已测输入的结论，不泛化所有输入。
- 固定长度 129／513／2049 token、batch 1／4／1、输出 32 token 的热运行矩阵几何平均 1.118×，达到冻结的 1.10× 目标；仍将对最终编译选项复测。
- 随机 learned 路由压力测试暴露第二个问题：对齐 forced routes 后误差仍大，排除仅由 argmax 翻转导致。单投影探针定位到 Inductor pattern matching 对二维分组张量的算子融合；关闭 `pattern_matcher` 后探针恢复一致，正在跑端到端复验。失败报告保留，不能当通过结果。
- EvalScope 1.0.0 在独立 Python 3.12 环境导入成功，递归依赖已补齐，未替换系统或模型环境 torch。vLLM 锁定版本依赖探针在有限网络排障时间内未完成，因此本版按既定 fallback 采用 Transformers Qwen；没有声称 vLLM 运行不兼容。
- 两个 HTTP 服务的并发 4 请求 greedy 对照通过，prompt 指纹和输出一致。LCB 官方 runner 外增加 Landlock／seccomp 限制，因为本机无容器运行时且禁止新 namespace；实际探针已验证读取 `/etc/passwd`、网络 socket 和文件写入被拒绝。下一步验证官方判题和数据链路。

## I3 数据与 pilot 决策

- ModelScope API 经当前可用代理返回连接错误；Hugging Face 可用。四个小集合已从原作者／维护者仓库按 commit 固定，并保存原始文件 SHA256、抽样记录哈希。LCB 原始 release_v5 拼接约 4.3 GB；目标日期属于新增 `test5.jsonl`（约 558 MB），先固定此增量并按日期过滤，明确不声称扫描了整个拼接发布集。采用校验 Content-Range 的并发断点下载，最终校验仓库 LFS SHA256。
- pilot 每集 16 题；正式快速回归每集 32 题。Redux／C-Eval 固定四个学科，数学按五个难度分层，其余固定 hash 排序。1024 token 输出上限、相同 non-thinking 采样配置、基于 prompt 的请求 seed。选择算法不读取模型分数，pilot 和正式集合可追溯。
- LCB 已用官方 runner 验证已知正确程序通过、错误程序不通过；其外层会吞部分异常，因此额外保留基础设施失败列表，结束时失败则拒绝验收。
- 扩大 mixed forced 测试后，BF16 RMSNorm 编译 reduction 仍可放大误差；保守方案是仅对 mixed 路径把 norm／residual 留在 eager，线性层和 MLP 继续真实编译，固定路径保持已验证完整投影编译。该边界明确记录，不做运行失败后的静默 fallback。
