# 动态循环实施记录

## 2026-09-30：开始实施

- 用户授权实施已确认的动态循环计划、使用全部 GPU 0–7，过程中自行作保守决策并频繁提交记录。
- 基线为 `2ff4f41`；保留固定 36 次路径及既有实验报告。动态训练、数据和报告使用独立目录。
- 起步采用最小 36、最大 48、连续两次稳定；逐 token 退出，冻结 hidden 并向更深循环保留最后实际计算的 K/V。训练保留跨这些 K/V 的梯度。
- 先实现可检查的矩形缓存参考，明确其存储仍随最大深度增长。随后跳过不活跃 token 的投影／FFN，测量实际性能，不以 mask 数量代替加速证据。
- 顺序：模型语义及 tiny 测试 → 训练／导出／恢复 → 真实 4B 深度路径与退出诊断 → 独立数据与 32B 离线蒸馏 → 配对训练及验收。参数与阈值由记录的小实验确定，不按 benchmark 选配置。

## 第一阶段：模型语义与 tiny 训练

- 当前开发分支为用户工作区中的 `0930_v0.0.4`。新增配置上限、尾部先验、H／P／H+P 固定退出，以及强制逐 token 深度轨迹（用于可归因正确性测试）。固定模式保持旧数值路径。
- active mask 只参与退出和执行选择；保留的 hidden/K/V 不 detach。已退出 token 的投影及 FFN 跳过；所有 token 退出后只填充逻辑 cache，不继续执行 cell。混合 active 的 attention 暂保留矩形参考计算，不宣称完整稀疏 attention。
- P 使用分块完整词表 JS，重算前后两个读出以控制内存；这是额外计算，性能统计必须计入。H+P 连续 H 达标后启动概率检查点。
- 新增 8 个测试覆盖 H/P/H+P 的全序列与分块 cached decode、未来后缀隔离、异构退出及早停 K/V 梯度、重计算梯度一致、固定深度等价、packing、padding、导出与非法配置。全套 CUDA 测试 38 passed（14 条原有弃用警告）。
- 两卡 tiny FSDP2＋重计算＋动态训练、HF 导出、同进程下一步 loss／参数摘要精确重放通过；独立进程恢复正在验证。随机深度以 seed＋optimizer step 决定，所有 rank 一致，不消耗不可追溯的额外 RNG。
- 32B 教师固定 revision `9216db5781bf21249d130ec9da846c4624c16137`，开始流式下载并校验权重 SHA256。环境代理可用，直连探针失败；不记录代理凭据。
