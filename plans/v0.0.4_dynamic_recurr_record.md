# 动态循环实施记录

## 2026-09-30：开始实施

- 用户授权实施已确认的动态循环计划、使用全部 GPU 0–7，过程中自行作保守决策并频繁提交记录。
- 基线为 `2ff4f41`；保留固定 36 次路径及既有实验报告。动态训练、数据和报告使用独立目录。
- 起步采用最小 36、最大 48、连续两次稳定；逐 token 退出，冻结 hidden 并向更深循环保留最后实际计算的 K/V。训练保留跨这些 K/V 的梯度。
- 先实现可检查的矩形缓存参考，明确其存储仍随最大深度增长。随后跳过不活跃 token 的投影／FFN，测量实际性能，不以 mask 数量代替加速证据。
- 顺序：模型语义及 tiny 测试 → 训练／导出／恢复 → 真实 4B 深度路径与退出诊断 → 独立数据与 32B 离线蒸馏 → 配对训练及验收。参数与阈值由记录的小实验确定，不按 benchmark 选配置。

## 第一阶段：模型语义与 tiny 训练

- 当前开发分支为用户工作区中的 `0930_v0.0.4`。新增配置上限、尾部先验、H／P／H+P 固定退出，以及强制逐 token 深度轨迹（用于可归因正确性测试）。固定模式保持旧数值路径。
- active mask 只参与退出和执行选择；保留的 hidden/K/V 不 detach。已退出 token 的投影及 FFN 跳过；所有 token 退出后只填充逻辑 cache，不继续执行 cell。混合 active 的 attention 暂保留矩形参考计算，不宣称完整稀疏 attention。
- P 使用分块完整词表 JS，重算前后两个读出以控制内存；这是额外计算，性能统计必须计入。H+P 连续 H 达标后启动概率检查点。
- 新增 8 个测试覆盖 H/P/H+P 的全序列与分块 cached decode、未来后缀隔离、异构退出及早停 K/V 梯度、重计算梯度一致、固定深度等价、packing、padding、导出与非法配置。全套 CUDA 测试 38 passed（14 条原有弃用警告）。
- 两卡 tiny FSDP2＋重计算＋动态训练、HF 导出、同进程下一步 loss／参数摘要精确重放通过；独立进程恢复正在验证。随机深度以 seed＋optimizer step 决定，所有 rank 一致，不消耗不可追溯的额外 RNG。
- 32B 教师固定 revision `9216db5781bf21249d130ec9da846c4624c16137`，开始流式下载并校验权重 SHA256。环境代理可用，直连探针失败；不记录代理凭据。

## 真实 4B 首轮验证与保守路径选择

- tiny 独立进程恢复通过（两卡、下一步 loss 4.529150485992432、参数 SHA 相同）。
- 真实 4B 异构退出轨迹覆盖 36–48 次：全序列与逐 token cache、compile 与 eager、HF remote-code 导出重载在这组已测输入上的 logits 差均为 0；参数计数 4,022,561,984。此结果不推广为任意输入／batch 的逐字节保证。
- 初始开发诊断仅取历史 pilot 的两个 512-token pack：原 36 次 CE=3.88071；cycle 40／48 为 5.13193／5.11660，tail 40／48 为 3.98095／4.55501。因此先选择尾部 8 套复用作预热先验，记录追加深度尚无初始质量收益。
- 四卡真实模型随机深度预热 32 步完成，前 4 步固定 36，之后按预设概率抽取 36／40／44／48；HF 导出与同进程精确恢复通过，独立进程恢复正在执行。这里的 off_layer_fraction 仍按原始循环层序统计，因此尾部固定复用也会计入偏离，不能视为学习 router 已改变路径。
- 语料整 shard 下载过慢，改用官方 dataset-server 分页并强制核对 `x-revision` 与固定仓库 SHA，保存页面和哈希。Infinity-Instruct Gen 返回 401，明确替换为公开 OpenCoder `filtered_infinity_instruct` 中的中文条目；不声称已经取得原 Gen 子集。
- 教师单连接速度偏低，HTTP／SOCKS 备用代理及直连／镜像探针未成功；改为可恢复的有界并行 Range 请求，校验每段 Content-Range，完成后仍须匹配原始 LFS SHA256。尚未完成的权重不加载为教师。

## 数据冻结、编译训练问题与校准

- 扩展语料已冻结：train 20,109 条／10,498,188 输入 token／7,459,764 targets；独立 halt_calibration 682、dev 658、test 917 条。来源涵盖通用、数学、代码及中文；中文公开替代来源保留 604 条，未用翻译伪造目标配比。具体域分布、页面哈希、223 条疑似评测来源排除及筛选范围见 corpus_manifest。
- 4B 随机深度预热的独立进程恢复通过：下一步 loss 2.704028844833374，全部参数摘要一致。
- 两卡混合路由＋H+P＋compile＋重计算的首次反传暴露 CUDA graph 录制／重放张量生命周期错误。保留失败配置及报告；修复为训练数值 kernel 继续使用真实 Inductor，但显式关闭训练 CUDA graph replay。推理 replay 保持开启。
- 修复后的 tiny compile 训练、同进程及独立进程恢复均通过；这是可变路由／深度的兼容性修复，不是静默退回 eager。完整测试扩展至 40 项，均通过。
- 首轮 H 校准网格下界 0.1 对预热后模型偏大，平均深度最高仅 38.37，未达 39–41 区间；保留该失败网格，增加预设较小阈值进行一次有界扩展。P／H+P 同时独立校准。初期仅用校准 split 的四个 512-token pack，范围写入报告，不假装已经完成全校准集验收。
- 下载 Range 并发从 48 调整到 192 后进度显著改善；仍有界重试、完整 SHA 校验，不修改教师权重格式或精度。

## 启动固定深度与真正动态训练对照

- 三种策略在同一初步校准样本上均找到 39–41 的候选：H 阈值 0.075、平均 39.20；P JS 阈值 0.0065、平均 39.48；H+P 的 H 阈值 0.2／JS 阈值 0.05、平均 40.12。初始 H+P 的 H=0.1 最低平均仍约 41.06，保留未达预算的诊断，再提高 H 门槛做有界复核。
- 增加 `learned_routing_start=36`：前 36 次严格走原层序，追加部分才训练专家 router；`off_prior_fraction` 单独衡量相对所选尾部先验的路由变化，区别原 `off_layer_fraction`。
- 固定 36、固定 40、H、P、H+P 均从同一个 32-step 随机深度预热 HF checkpoint 分叉，用同一新增训练数据、seed、1024 长度和 64 步。动态组预设 10% 强制上限批次，全部计入计算和平均深度。这是相同 token／相同初始化的阶段性对照，不是同 GPU-hours，也不是未经预热的原生模型训练对照。
- 四卡一组运行固定／H／P，另一组运行 H+P；每个正式候选均启用保存、HF 导出、同进程和独立进程精确恢复。正式候选保持 eager 数值投影，compile 兼容性与推理性能另测。
- 全部测试已扩展至 41 项通过。推理 HTTP 元数据加入退出规则与阈值，响应中区分 prefill／decode 深度统计，避免评测缓存混淆不同停止策略。

## 首批正式训练完成，进入独立验收

- 固定 36 与 H+P 的 64-step 训练、同进程重放及独立进程恢复均通过。当前相同 8 个开发 pack 的 CE 分别为 0.93759、0.95682，不能据此宣布动态收益；继续在完整新 dev 与 calibration 上检查。
- 新增完整文档的独立 CE／退出分布评估、batch 1／4 cached generation 的 eager／compile 测量脚本，以及原生／学生／32B 的完整词表和实际模板前缀对齐审计。
- 32B 权重 Range 完成进度约 31.8 GiB／61.0 GiB（按已校验响应并落盘的分段位图统计，不按稀疏文件表面大小）；最终仍需完整 SHA 校验后才能加载。
- 大教师数据准备脚本要求所有 worker 的身份、选择集和完成状态一致，截断／非完整 non-thinking 答案不进入监督；数学采用 math-verify 0.8.0 核验源答案，Python 代码只有语法检查时明确标记，不声称代码正确。独立评测环境安装该工具后 latex2sympy2-extended 从 1.11.0 变为 1.10.2，后续评测须记录这一环境变化，必要时恢复原环境保持旧分数可比。

## 完整开发集与推理测量首轮结果

- 新 dev 共 658 个完整文档，原生 Qwen3-4B assistant CE=1.40185；固定 36 继续训练 CE=0.81032。它衡量对当前四域来源答案的条件似然，不能等同官方能力分数；尚未读取盲测 test 来选择配置。
- H+P eager／compile 测量完成，batch 1／4 各预热后重复三次、生成 32 token：编译吞吐 13.61／51.34 token/s，加速 1.092×／1.022×；已测 greedy token 完全相同，真实捕获 7／11 个图。显存约 8.25／8.29 GB（allocated）。不同任务共享机器，数字只代表本次运行条件。
- 上述提示 prefill 和 decode 均停在 40 次；H+P 存在接近固定深度的退化分布，不能以动态实现已经工作代替内容自适应收益证据。新增同权重固定 36／40／48 与动态的逐 token NLL／top-1 诊断，且明确这些指标不等于完整答案正确性。
- 数学筛选依赖已隔离到 artifacts/math_verifier；官方 `.venv-eval` 的 latex2sympy2-extended 已恢复 1.11.0。原生／学生／32B 的完整词表映射、特殊 token 和实际模板前缀均一致；未按误触发的 Mistral regex 警告修改 Qwen tokenizer。

## 校准预算通过，但尚无动态质量收益

- H+P 在完整独立校准集 682 文档上平均 40.01387，dev 658 文档平均 40.01369，预算达标；dev CE=0.83020，固定 40 为 0.82993，均差于固定 36 的 0.81032。
- 同一个预热模型的完整 dev 固定 36／40／48 CE=0.89915／0.92954／1.09903；因此预热本身未使更多深度获得收益。H+P 已训练权重的 64 文档诊断同样显示继续到 48 更常损害 NLL；完整数值与适用边界见 exit_diagnostic，不能把标签 top-1 不符直接称为答案错误。
- 三组已经完成的训练均实际使用 201,355 输入 token／143,914 targets；固定 36、固定 40、H+P 的纯训练 step 时间合计约 36.2／48.2／74.9 秒，H+P 训练平均 40.553 次（包括强制 48 批次）。启动、验证、保存和恢复开销另计，不能只用 step 时间宣称端到端训练成本。
- 新增两项行为测试通过：七类线性投影的真实 forward hook 计数等于实际存活 token-depth 总和；混合退出历史经 batch 重排／复制再 decode 与完整前向一致。
- 大教师答案筛选增加源文件、worker 输出 SHA 及原始 prompt 一致性检查，并输出完全相同接受 prompt 的原来源答案对照集。后续强教师实验采用相同初始化的固定／动态学生，同时设置源答案对照，避免把 prompt 变化误当教师收益。
- 数学筛选发现裸表达式解析可能提取内部数字，例如 `13==11×182-3×663` 被误读为 11。改为完整 LaTeX gold 表达式解析，正确／错误数字、等价分数及此反例四项控制均通过；无法核验的数学答案继续排除。

## 空 rank、校准漂移及生成预算核验

- 两卡 FSDP2＋重计算的独立梯度参考测试通过：全空 rank 对混合退出 rank、混合退出 rank 对全部触顶 rank，37 个有梯度参数逐个比较，最大绝对误差均为 0。相关行为测试为 13 passed，全套最终回归待后续代码收尾执行。
- H 的 64-step 训练和独立恢复通过；沿用训练前阈值 0.075 时完整 calibration/dev 平均仅 38.20478／38.20277，未达 39–41 预算。保留原报告，单独在 calibration 的 32 个 pack 上重新扫描阈值；训练规则不回写，后校准只生成新的 HF 配置变体，再做完整文档预算检查。
- 新增校准 prompt 的真实生成测量，区分 prefill 与 decode 均值，不从 teacher-forcing 深度推断部署预算。只测深度与成本，短输出不冒充能力评分。
- 数据独立审计通过所有 split 的 SHA、计数、规范化题干／ID 互斥及 labels 对齐。来源卡声明及卡 SHA 已独立记录；实际中文替代来源遵循 OpenCoder 卡，未挪用不可用 BAAI Gen 的来源声明。

## 第一轮五组恢复全部通过，移除不可能影响退出的概率检查

- 固定 36／40、H、P、H+P 五组四卡训练均通过同进程及独立进程精确恢复；这些报告对应优化前的源代码身份，继续保留，不以新源码冒充重新恢复通过。
- P 在最小深度 36 之前进行了大量完整词表读出。仅最后 `patience` 个检查能够构成首个合法退出窗口，因此新增默认开启的 `defer_probability_checks`，将 P/组合策略的早期无效概率计算跳过；H+P 的历史检查点仍正常更新。可关闭该开关保留未优化数值参考。
- 新增 P 和 H+P 的读出次数、logits、退出原因／深度及全部梯度的严格等价测试。完整回归 45 passed（14 条原有警告）。训练 checkpoint 配置同步 num_hidden_layers/layer_types 与 num_recurrences，修正原先仅元数据滞后的问题。
- 追加当前源码的真实 4B compile＋FSDP2＋重计算短训／重启验证；不修改正在恢复的实验代码。推理元数据记录是否推迟概率检查，避免性能缓存混淆。
- H 完整文档阈值 0.05 平均 38.89266，未通过完整预算。按事先网格相邻值改为 0.04 后，完整 calibration 平均 39.64310、触顶率 4.62%，成为合格候选；所有失败／偏差记录保留。

## 收敛判据诊断与教师试跑反馈

- 延后概率读出的真实 4B 样本验证通过：256-token 前向及分块 cache logits 最大差均为 0；P 前向从 0.4521s 到 0.1680s（2.69×），H+P 从 0.1850s 到 0.1602s（1.15×）。这是特定前向的测量，不冒充完整生成吞吐。
- H 的完整校准阈值 0.04 在 dev 上 CE=0.84032、平均 39.559；P 后校准阈值 0.001 在完整 calibration 上平均 39.029。H+P 的 dev CE=0.83020 仍优于此 H 候选，但固定 36 继续训练更好。
- 固定展开的 16 个校准前缀诊断发现明显深度相位：第 38 次连续两次 H 稳定的 token 中，95.30% 在下一步重新不稳定；第 46 次对应比例 96.86%。相邻稳定很可能受专家身份／残差幅度影响，不能解释为已经到达固定点；lag-1/2/8 统计已保存，后续不据此盲目加深。
- 32 题官方回归：固定 36 与 H+P 的 MATH 均 26/32，IFEval strict 分别 21/32 与 17/32；旧原生同子集为 27/32、23/32。仅作小集观察，未按这些分数选择阈值，最终仍需冻结候选后的完整回归。
- 32B 单卡 20 条试跑完成，输出 15,982 token，总 worker 时长 443s；1024 输出上限造成 10 条截断，另有 2 条数学未通过核验，最终 8 条合格。正式 1k 将上限提高到 2048，截断答案仍排除；不会将这种筛选后的题目难度变化隐藏掉。
- 数据来源审计发现 OpenCoder 的 largescale_diverse_instruct 本身混合普通问答：D1 train 中 5,346 个该来源条目仅 3,009 个匹配显式编程线索。原 domain 字段按来源桶解释，不能当作严格语义类别。正式教师的 code 配额增加编程线索筛选；原冻结语料、旧实验和未筛选 pilot 保留。新筛选仍是启发式，不宣称代码正确性。
- 当前只继续已计划的 1k 教师受控实验，固定／动态学生使用完全相同数据，并保留匹配 prompt 的源答案对照；50M–100M 池或 10k–50k 教师扩容不启动，因为还没有额外循环收益依据。

## 冻结 32B 1k 与下一阶段配对协议

- batch 8 的 10 条试跑完成，峰值 allocated 69.45 GB；正式 1,000 条已在 GPU 0–7 八个独立 BF16 HF 副本启动，batch 8，最大输出 2048，固定 non-thinking 采样和 prompt 集。权重／模板／选择器／生成脚本身份写入每个 worker；生成期间不改动相关代码。
- 本轮所有预算合格候选在完整 dev 上仍差于固定 36：固定 40、H、P、H+P 的 CE 增量分别约 +0.01961、+0.02999、+0.04499、+0.01987。成对文档 bootstrap 区间仅描述这一训练 seed／来源数据，不替代多 seed 的能力结论。
- H 最终阈值 0.04 的生成校准 prefill/decode 为 40.468／40.065；P 阈值 0.001 为 40.108／38.593，存在 decode 预算偏低。保留此偏差，不静默改成另一套部署规则。
- 32B 主动态候选预先选择 H+P：独立 dev CE 在三种动态方案中最低，完整校准及生成预算稳定。官方小集分数不参与该选择；H 的速度更快但 CE 较差，并有明显相位平台问题。
- 冻结五个 64-step、四卡、2048 长度、compile 训练配置：教师答案固定 36／固定 40／动态 H+P，另有固定 40＋同 seed/step 的 10% 强制 48 对照，以及匹配接受 prompt 池的源答案固定 36。它们从同一个随机深度预热 checkpoint 起步，4B KL 权重相同。
- 额外 anchor40 控制避免把强制 48 的日程效果误当成动态退出效果。源答案与教师答案长度不同，实际 token／prompt 曝光会单列，不声称只改变了教师参数规模这一因素。
