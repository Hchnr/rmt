# Audit Qwen3-0.6B training and stabilize deterministic cached inference

## Changes

Move to Qwen3-0.6B with 28 bound experts and an original-order control. Add actual supervised-token budgets, teacher-free CE training, retokenization, exposure audits, and a physical GPU 4–7 restriction. Fix mixed-precision QKV dispatch.

Enable deterministic inference by default, add a preallocated native Qwen KV cache, and avoid repeated full-history decoding. Retain packing, compile, FSDP, activation checkpointing, and HF export/resume support.

## Validation and findings

- Regression suite: 57 passed. Tested untrained eager logits, cached decode, and HF reload match the reference.
- Native capacity cache: 96 real-model comparisons match HF DynamicCache bitwise.
- Six independent fixed28 runs cover CE/KL, training duration, data coverage, and learning rate. Five fresh resume/export checks pass; the 250k follow-up is queued.
- MATH-500: native 49.20%, candidate 47.00%; paired difference −2.20 pp, bootstrap 95% interval [−6.00 pp, +1.80 pp]. IFEval is still running.
- Best development candidate: instruction 45/48 versus native 46/48; math 48/48 for both. It fails the predeclared 2 pp engineering gate, so 10M/30M dynamic training and new 32B generation were not started.

P1 is an original-depth SFT/KL control and establishes no extra-depth or adaptive-exit benefit. Formal tests do not select recipes; equal output caps are not equal actual compute.
