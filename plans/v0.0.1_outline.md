# RMT v0.0.1：研究与工程路线大纲

更新日期：2026-09-29。本文用于讨论并确定总体路线；具体模型、训练、推理和评测实现另开 plan。

状态约定：**已确定**来自项目要求或本轮讨论；**建议**是工作方案；**待讨论**尚未形成决定。效果和效率均以实验验证，不预先保证。

## 1. 目标与已确定范围

验证 RMT（Recurrent Mixed Transformer）：基于 **Qwen3-4B**，将深度堆叠改成单个循环 Transformer cell，在相近总参数预算下，通过成套专家的路由与跨循环复用，研究能力和计算效率。

已确定：

- 基座采用 Qwen3-4B，第一阶段只做纯文本，多模态后续单列。
- **首轮将 Q、K、V、O 和 FFN 的 gate、up、down 绑定为完整的一套专家**，套内七类投影共用同一个专家选择；各套保有独立可训练的权重。
- **专家套数先取原模型的 `n_layer`，即 36 套；解除绑定、投影独立路由留作后续实验。**
- 总参数保持约 4B；**首轮固定 36 次循环**，验证后再扩展退出机制。
- 先蒸馏 Qwen3-4B、达到约定的同等能力标准，再蒸馏更强 Qwen。
- 训练必须支持 packing、compile、FSDP、重计算，并验证组合使用。
- 交付以 Hugging Face 格式 checkpoint 为基础，支持 batched inference，并测量实际性能。
- 评测集合以 Qwen3 技术报告为依据，建设可复用、可追溯的基础设施。
- 资源为 **8 张 H100**，希望在 **24 小时内验证相近计算预算下超过原 Qwen3-4B 的质量收益**。

首轮研究固定 36 次的成套专家路由能否在相近计算预算下改善质量；后续再研究解除绑定、循环预算和更强教师。24 小时应产出支持或不支持假设的证据；完整评测上的追平／超越是后续验收目标。

## 2. 基座与参数口径

依据官方 [Qwen3-4B 配置][qwen-config]及[模型卡][qwen-card]：Qwen3-4B 使用 36 层同构 dense Transformer，采用 GQA，不存在 DeltaNet／full-attention 混合层的结构差异。因此，原深度对应 **36 次循环**。

| 项目 | 数值／定义 |
| --- | --- |
| 层数 | 36 |
| Hidden size / FFN intermediate size | 2560 / 9728 |
| Q / KV heads；head dimension | 32 / 8；128 |
| 词表 | 151936 |
| Embedding 与 LM head | 绑定权重 |
| 基础教师建议 | `Qwen/Qwen3-4B` 后训练版，保留 thinking / non-thinking 能力 |

按配置推导并与 HF 权重元数据核对，原模型有 **4,022,468,096 个唯一参数，约 4.022B**。后续参数统计以实际 tensor 为准，绑定权重只计一次。

首轮建议固定原始 Qwen3-4B 后训练版作为初始化和教师，便于对齐技术报告；不混入 Base 或其它后续版本的分数。实验固定模型 revision、tokenizer、chat template、数据与软件版本。

## 3. 模型结构路线

### 3.1 单个循环 cell 与 36 套绑定专家

计算顺序沿用 Qwen3 的 pre-norm、attention、残差、FFN、残差结构；每次循环执行一次完整 cell。所有循环访问同一个成套专家池，各专家可在不同循环步复用。

**已确定：专家套数 `E = n_layer = 36`。** 建议第 e 套由原第 e 层的全部投影初始化，初始采用 top-1。每次路由产生一个专家索引 e，Q/K/V/O/gate/up/down 全部使用第 e 套参数；这个选择保持到本次 cell 计算结束。套级 router 建议在循环步之间共享，并接收循环步信息。

专家套数 E 与循环次数 R 是两个不同配置；首轮都为 36，后续调整循环次数时不要求同时改变专家套数。

| 套内投影 | 每套的输入 → 输出维度 | 36 套合计参数 |
| --- | --- | --- |
| Q | 2560 → 4096 | 377,487,360 |
| K | 2560 → 1024 | 94,371,840 |
| V | 2560 → 1024 | 94,371,840 |
| O | 4096 → 2560 | 377,487,360 |
| gate | 2560 → 9728 | 896,532,480 |
| up | 2560 → 9728 | 896,532,480 |
| down | 9728 → 2560 | 896,532,480 |

36 套专家中的七类投影共 3,633,315,840 参数，加 embedding/head 的 388,956,160 参数和 norm 的 196,096 参数，恰好构成原模型；新增套级 router／循环步信息另行列账。绑定改变投影的选择方式，保留原有权重参数预算。以上为基于官方配置的本项目推导。

Norm 与输入输出模块的建议边界：embedding/head 和 final norm 共享；Q/K norm 及两处 pre-norm 随整套专家携带，使用同一个专家索引，保留原层内的参数配套关系。后续解除绑定时再定义各 norm 的归属。

总参数目标建议为原模型的 ±5%，正式实现前确认；top-k、专家数、专家宽度都必须记入预算。循环次数增加计算但不增加专家权重。报告总参数、每次循环激活参数、累计 FLOPs、实际延迟、显存和缓存用量；36 次 top-1 不自动比原 36 层更省计算。

### 3.2 初始化与成套专家路由

1. **固定路径校验。** 第 r 次循环选择由原第 r 层初始化的完整专家套，norm 同步对应，关闭新增扰动；应能在数值容差内复现原模型 logits 和生成。该模式用于验证权重转换。
2. **逐步开放套级学习路由。** 建议 router 输入使用进入 cell 时可见的 token 表示与循环步信息，保持因果性。可以从原层选择先验开始，逐步学习专家选择，保持套内绑定。
3. **正式 RMT 训练。** 每次选择完整专家套，允许专家跨循环复用；记录各套使用率、路由熵、专家选择序列、跨循环复用和偏离原层路径的比例。

首轮需要验证：原层作为成套专家后，能否适应不同循环位置的输入分布，并通过学习选择顺序和重复使用获得收益。套内保持原 Q/K、V/O、gate/up/down 配套关系；同一 token 内跨原层混搭投影的兼容性留到解除绑定实验验证。

Router 必须有明确可验证的梯度方案。不能直接用不可导 argmax 并假定其可学习，也要避免 top-1 概率归一化为常数 1 后丢失任务梯度。具体采用保留门控权重、直通估计或其它松弛方案，由结构 plan 对比小实验决定。

首轮建议不丢 token；路由辅助损失、探索强度和负载均衡可调。固定路径复现教师属于工程校验；开放套级学习路由后的结果用于研究 RMT。若最终仍退化为原固定层序，应如实报告。

### 3.3 Attention 与缓存语义

建议首轮采用 **token 级套级路由 + 标准因果 GQA**：每个 token 在某个循环步选定一套专家，整次 cell 计算使用该套的七类投影。Q 读取该循环步所有合法历史 token 已产生的 K/V，不按专家 ID 隔离可见历史。

- 首轮 KV cache 按 `(request, recurrence_step)` 保存已经投影并按原规则处理的 K/V；不为每套专家另建完整历史缓存。
- 历史 token 的 K/V 由其当时选择的专家套产生并保留；后续 token 改选专家时不回头重投影旧 token。不同 token 仍可能选择不同套，因此跨 token 的 Q/K 表示兼容性仍需训练和验证。
- 不同循环深度使用不同 hidden state，因此不直接共用 KV cache；共享权重不意味着缓存缩为原来的 1/36。
- 序列位置与循环深度分开；RoPE 的 token 位置不会随着循环递增。
- 必须验证全序列 forward、分块 prefill 和逐 token cached decode 的一致性，以及批量组成变化不改变路由／因果语义。

上述语义是建议路线；实现 plan 应明确 norm 顺序、router 输入与训练梯度，而不是训练和推理分别采用不同模型定义。

### 3.4 后续解除绑定实验

绑定专家基线稳定后，再研究解除绑定。建议从同一个绑定 checkpoint 分支，保持各投影原有权重和专家数量，对比成套选择与分组／逐投影选择。

可以先解除 attention 与 FFN 之间的绑定，再探索 Q/K/V/O/gate/up/down 分别路由；具体顺序在后续实验 plan 确定。解除绑定新增的 router 参数与 dispatch 成本单独统计，并使用相同数据、训练 token、循环次数及评测协议比较质量与效率。该实验不纳入首轮 24h 必做范围。

## 4. 循环次数与退出机制

**已确定：首轮固定 R=36，完成验证后再扩展退出机制。** 以下保留候选方案供后续选择。后续相邻预算可从 28、32、36、40 中选少量点；非 36 次需要相应训练或校准，不能只改推理循环次数就默认保持效果。

| 方案 | 退出方式 | 取舍 | 建议位置 |
| --- | --- | --- | --- |
| E0：固定循环 | 每个 token 固定 R 次 | 训练、compile、batching 最直接 | **首轮已选：R=36** |
| E1：请求级预算 | 请求开始时选择 R，整个请求保持 | 能按质量／时延分档；需多深度训练，同 R 请求分桶 | 优先扩展 |
| E2：稳定性阈值 | 根据表示变化或输出分布稳定性停止 | 阈值需校准；重复 LM head 投影有额外成本 | 探索方案 |
| E3：可学习退出 | halting head／ACT 类机制，加入计算代价约束 | 能适应 token 难度，但训练、缓存和动态 batching 最复杂 | 后续研究分支 |

E2/E3 设最小／最大循环次数，报告退出分布与实测收益。逐 token 提前退出会使历史 token 缺少深层缓存，必须定义并验证补算、状态投影或其它方案。E1 从请求开始保持同一深度，可先避开这类缺层问题。循环停止与生成 EOS 分开定义。

## 5. 蒸馏训练与能力验收

| 阶段 | 工作 | 进入下一阶段的条件 |
| --- | --- | --- |
| T0：基线与迁移 | 固定教师、数据和评测协议；原各层参数搬入成套专家池；验证兼容路径 | 参数、logits、缓存、导出加载和短训练正确 |
| T1：Qwen3-4B 蒸馏 | 学习成套专家路由，恢复并保持教师能力 | 核心评测达到预定非劣标准，完整评测覆盖与例外可追溯 |
| T2：更强 Qwen 蒸馏 | 从 T1 最优模型出发，选择 Qwen3-8B／14B／32B 等教师 | 相对 T1 的能力改善可复现，新增教师成本明确 |
| T3：循环预算优化 | 多深度训练、深度扫描、选定退出方案及消融 | 得到能力—实际延迟—显存曲线 |

T1 先达标再扩大教师是总体顺序。首轮集中在 R=36、E=36 的绑定专家质量实验；解除绑定、更强教师、循环预算扫描和动态退出不纳入首轮必做项。

**训练目标建议：**任务／教师序列 CE + teacher→student token 分布 KL + 必要的 router 辅助损失。中间表示对齐可选；约束过强可能抑制专家选择与跨循环复用，应做消融。

首轮追求超过 4B 教师时，单独最小化同一教师的 KL 缺少直接奖励“比教师更好”的信号；等价初始化的固定路径已经能拟合教师。因此建议加入高质量标注答案、可验证的数学／代码答案等监督信号，用 KL 约束通用能力退化，并让原架构对照使用相同数据与目标。能否出现架构收益仍由实验证明。

**教师与数据路线：**

- 4B 阶段优先实现冻结教师、teacher-forcing 下的分块 logits KL；原生完整词表目标作为正确性参考。按显存选择每卡教师副本或独立教师资源，但所有资源计入 8 卡预算。
- 在线教师方案先短跑测端到端吞吐；若教师显著拖慢，再考虑离线分布缓存。top-k 缓存需保留索引、温度、归一化和尾部质量，并标记近似目标；用小样本完整 KL 检查偏差。
- 离线教师生成数据可复用；更强教师优先批量生成答案／推理轨迹，再按收益决定是否投入在线或 on-policy 蒸馏。
- 教师与学生 tokenizer 兼容才能直接逐 token KL；不同词表优先序列蒸馏，另行规划对齐。
- 训练集覆盖中英文通用、数学、代码、指令和适量多语；首轮建议 packing 到 2K／4K，长上下文放在后续课程。长推理轨迹单独保留长度策略，不把被截断的答案当完整监督。
- thinking 与 non-thinking 数据显式标记；prompt、assistant、thinking、padding 和样本边界的 loss mask 统一。
- 固定训练／验证／测试划分，对官方评测题及其衍生样本去污染；数据来源、混合比例、token 预算在训练 plan 冻结。

“达到一样水平”需在正式训练前约定：按能力类别和逐任务报告分数差与不确定性。可讨论同量纲类别均分下降不超过 1 个百分点、关键单项不超过 2 个百分点的初始容差；小样本与 judge 任务另订口径，置信区间过宽时结论应为未确定。不能只凭训练 loss 或少量示例宣布追平。

## 6. 8×H100、24 小时首轮验证

**已确定资源：8 张 H100。** 单卡显存、SXM／PCIe、互联与存储带宽在运行前记录，不默认已知。24 小时暂解释为代码、模型和基础语料就绪后的首轮实验窗口；本轮新增教师生成、训练和评测均计入预算，提前准备的数据成本另行列账。

**首轮收益目标已确定：相近计算预算下，质量超过原 Qwen3-4B。** 主模型使用 E=36 套绑定专家、固定 R=36、建议 top-1。主要以相同输入／输出 token 预算、thinking 模式和实测／核算 FLOPs 约束推理计算；暂建议允许不超过 5% 的 FLOPs 差异，正式实验前确认。真实延迟和吞吐另行报告，计算量接近不代表用时接近。

训练侧固定数据顺序、有效训练 token 数与可比优化设置。必须同时比较冻结的原 Qwen3-4B 和继续训练的原架构对照：前者判断是否超过起点，后者帮助判断提升是否来自 RMT。两条训练及教师、评测资源全部纳入 8 卡、24h 总预算。

开始前冻结一个主质量指标、最小有意义的提升幅度和关键能力退化容差；尽量用相同题目的配对差异估计不确定性。候选指标可为固定核心集中同量纲任务的宏平均，具体任务权重在实验 plan 确认；不得看到结果后挑选有利任务。首轮证据不足时结论为未验证收益。

| 时间窗口【建议】 | 工作与产物 |
| --- | --- |
| 0–2h | 教师与学生固定回归子集、迁移正确性、packing／缓存检查、吞吐与显存 profiling；已有基线可复用并记录来源 |
| 2–4h | 少量学习率／router 设置短跑；确认 router 有梯度、套级学习路由开始生效、没有严重塌缩，选一个主配置 |
| 4–18h | RMT 与原架构继续训练对照各约 7h 上限；先按 profiling 选双方都能完成的相同训练 token 预算；定期保存 checkpoint 和固定开发回归 |
| 18–21h | 对选定候选做一次短复验或最关键诊断；新增训练影响公平性时，对照同步调整且计入预算，不临时增加深度扫描 |
| 21–24h | 独立留出集质量评测、batching 性能、路由统计，形成继续／调整／停止扩大预算的结论 |

实际 token 预算通过测得的端到端有效吞吐确定：每条训练的共同上限由 `min(S_RMT, S_control) × 各自可用训练秒数` 估计；计入教师、重计算、通信、评测暂停和保存开销。可以顺序使用 8 卡，或实测后分成两组并行，总卡时不超过 192 H100 GPU-hours。不能按理论峰值承诺 token 数或收益。

首轮必交付：

- 一个可加载的 RMT HF checkpoint、配置／数据／日志与原 Qwen 教师基线。
- 开放套级学习路由后的能力曲线、专家选择行为、有效训练 token 数、端到端 GPU 小时。
- 给出相近计算预算下相对冻结原模型和继续训练对照的质量差异；只有恢复能力时标为可行性信号。仅超过冻结原模型、未超过继续训练对照时，不把提升归因于 RMT 架构。
- 使用固定开发集选 checkpoint，再在独立留出集判断收益；小样本有波动时报告不确定，后续独立 seed 复验。

首轮不要求完成全部官方评测，但完整评测基础设施和后续验收范围不因此缩减。若兼容映射不正确、router 无有效梯度、持续 NaN 或有效吞吐无法支持实验，先解决阻塞原因再追加训练。

## 7. 训练工程与效率

**建议主线：PyTorch 模型核心 + FSDP2；优先评估复用 TorchTitan。** [TorchTitan][torchtitan] 提供 FSDP2、compile、重计算和分布式 checkpoint 等基础组件；成套专家 MoE、循环共享权重和蒸馏仍需适配。先做小规模集成验证，若侵入过大，采用薄层原生 PyTorch 训练循环，维持模型／数据／checkpoint 接口一致。[TRL 蒸馏实现][trl-kd]可作参考。

| 必须支持 | 实现路线与验收重点 |
| --- | --- |
| Packing | 使用带样本边界的 causal attention；隔离跨文档可见性，对齐 position、label shift、loss mask 和教师目标；packed 与单样本结果一致 |
| Compile | 固定 R、长度分桶，优先编译 cell／成套专家计算；记录 graph break、重编译、首次编译成本和稳态吞吐 |
| FSDP2 | 共享专家参数只注册／分片一次；不同 rank 的路由选择不能造成 collective 顺序分叉；FSDP 与 expert parallel 分别规划 |
| 重计算 | 按循环段 checkpoint；重算时路由和随机性一致；默认完整反传穿过全部循环，不以 detach 替代 |
| 四者组合 | 多卡短跑验证 loss／梯度、有限数值、恢复训练及吞吐，不以四个开关分别可启动作为完成 |
| 数值与内存 | BF16 主线，敏感 norm／loss 按需要保留高精度；大词表 CE/KL 分块；梯度累积、可恢复 dataloader |

首轮不默认上 expert parallel。重点 profiling：36 次循环的 FSDP all-gather、参数驻留与 reshard 策略、套级路由后的分组／scatter、小 GEMM、teacher 开销与重计算。套内可复用专家分组索引，但 attention 仍须保持完整因果历史，不能因按专家分组而隔离 token。评估在循环区间保留 unsharded 权重的内存／通信取舍；不得直接照搬普通深层模型的 wrap 策略。

绑定模式下优先保留套内 QKV／gate-up 融合机会，测量分组计算的实际代价；后续解除绑定时再比较融合机会减少与额外 dispatch 的开销。后续若通过减少循环获得加速，需要确认计算节省能够覆盖路由与访存开销。

## 8. HF checkpoint、推理与 batching

### 8.1 HF 格式交付

- 输入锁定 revision 的 Qwen HF checkpoint，保留可审计的原层→专家映射与参数统计。
- 输出 RMT 自有 config、safetensors、tokenizer、chat template、generation config；记录专家套数、投影绑定模式／分组、路由、循环／退出配置、norm 规则和缓存版本，便于区分后续解除绑定的 checkpoint。
- 依照 [HF 自定义模型规范][hf-custom]提供模型类、AutoClass 注册／加载方式，支持 `save_pretrained`、`from_pretrained` 和 `generate`。
- 分别验收 HF 推理导出和分布式训练恢复；后者还需 optimizer、scheduler、RNG、数据进度。
- 导出后在新进程加载，核对 logits、生成、绑定权重和循环配置。

### 8.2 必做能力与性能路线

先建立 HF/PyTorch 参考实现：单条与静态 batched inference、变长输入、prefill、增量 decode、padding、EOS 后回收／重排 KV cache。验证单条与批量、全序列与缓存解码一致；token 路由不可依赖同 batch 的其它样本内容。

首轮性能工作覆盖长度分桶、固定循环、按专家分组 GEMM、attention kernel、缓存预分配与 compile。测 TTFT、每 token 延迟、prefill／decode tokens/s、吞吐与峰值显存，覆盖不同 batch size、输入长度与输出预算；编译预热单独列账。

参考实现稳定后选择一个高性能后端，优先评估 vLLM；continuous batching、成套专家路由和循环 cache 作为独立适配项。HF 格式兼容不代表新架构自动受推理引擎支持，按[后端接入要求][vllm-custom]验证。

E1 按请求循环预算分桶；E2/E3 额外处理活跃 token 集合和缺失的深层 cache。所有速度结果在相同硬件、精度、输入输出长度、batch／并发和质量约束下比较。

## 9. Qwen3 技术报告评测与基础设施

以 [Qwen3 Technical Report v1][qwen-report] 的 §3.3、§4.6、附录 A.1.1 为来源。建设三个独立 manifest，避免把 Base、后训练和长上下文的协议混用；后训练部分为当前主要能力验收集合。

| 集合 | 任务清单 |
| --- | --- |
| Base：通用 | MMLU、MMLU-Pro、MMLU-Redux、BBH、SuperGPQA |
| Base：数学／科学 | GPQA、GSM8K、MATH |
| Base：代码 | EvalPlus、MultiPL-E、MBPP-3shot、CRUX-O |
| Base：多语言 | MGSM、MMMLU、INCLUDE |
| 后训练：通用 | MMLU-Redux、GPQA-Diamond、C-Eval、LiveBench（2024-11-25） |
| 后训练：对齐／写作 | IFEval、Arena-Hard、AlignBench v1.1、Creative Writing V3、WritingBench |
| 后训练：数学／推理 | MATH-500、AIME'24、AIME'25、ZebraLogic、AutoLogi |
| 后训练：Agent／代码 | BFCL v3、LiveCodeBench v5（2024.10–2025.02）、CodeForces／CodeElo |
| 后训练：多语言 | Multi-IF、INCLUDE、MMMLU、MT-AIME2024、PolyMath、MLogiQA |
| 长上下文 | RULER，各上下文长度单列 |

正式协议需复核重复采样、语言／数据子集、judge、工具格式和长上下文扩展设置。报告中的任务名一致不足以证明分数可直接比较；难以复现的项登记差异，不能静默替换。

基础设施路线：

- benchmark manifest 固定来源、数据 revision、split、few-shot、prompt、thinking 模式、采样、max tokens、重复次数、解析器、metric／judge 和执行环境。
- [lm-evaluation-harness][lm-eval] 承接合适任务，其余用官方 runner／专用 adapter。代码任务有执行环境，工具任务有工具环境，judge 模型及其费用单列。
- 同一接口评测教师、HF RMT 和优化推理后端，保存逐题输出、评分、失败日志、token 数、循环次数与耗时。
- 支持断点续跑、样本缓存、seed、结果聚合与置信信息；模型／数据／代码／judge 版本进入 run metadata。
- 分层运行：开发 smoke、24 小时固定核心子集、阶段验收完整集。首轮可选 MMLU-Redux、C-Eval、IFEval、MATH-500、LiveCodeBench 的固定子集，按计算预算冻结样本量；不冒充完整官方成绩。
- thinking / non-thinking 分开报告；首次主训练与快速回归模式在训练 plan 确定，两种能力都属于最终目标。
- 教师和学生在相同本地协议下比较；正式报告提供逐任务覆盖状态，未运行、失败、受资源限制的项不能算通过。

## 10. 对照、里程碑与后续 plan

首轮必需对照：冻结的原 Qwen3-4B；固定原层路径兼容模式；继续训练的原 Qwen3-4B；成套专家学习路由 RMT。两条训练保持相同数据、有效 token 数和可比目标。后续以绑定版本为基线，增加解除绑定、循环次数、路由辅助损失等消融。

更强教师阶段尽量增加使用相同蒸馏数据／预算的原架构对照，区分蒸馏和架构收益。一次小规模实验提供探索证据，重要结论后续用独立 seed 与完整集合确认。

| 里程碑 | 产物与验收 |
| --- | --- |
| M0：路线冻结 | 落实固定 36 次与质量收益目标，确定 norm／router 方案、数据、计算预算口径和软件版本 |
| M1：最小正确实现 | 小配置原型、4B 权重迁移、HF 导出、packing／缓存／梯度检查、批量生成通过 |
| M2：训练效率可用 | packing+compile+FSDP+重计算多卡组合短跑，确定实际吞吐和 24h token 预算 |
| M3：24h 可行性验证 | 可加载 checkpoint、质量／效率对照、路由行为、继续或调整的证据 |
| M4：4B 完整对齐 | 成套专家学习路由模型满足约定非劣标准，完整评测与例外可追溯 |
| M5：后续研究与优化 | 分别规划解除绑定实验、更强 Qwen 蒸馏、退出机制、高性能 batching 后端与能力—成本曲线 |

后续分别新建 architecture、training、inference、evaluation、experiments 实现 plan；本次只维护本大纲。
