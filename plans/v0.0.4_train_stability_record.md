# v0.0.4 实施记录

## 启动与现状

- 用户授权继续推进并频繁记录，GPU 0–7 全部可用；开始时八卡均空闲，工作区干净。
- 训练旧入口仅 16-token、5-step fixture smoke，且先验随步数快速归零；不直接复用于正式训练。
- mixed 路由 compile 性能未达标，但已有 correctness 参考。首先测真实长度，保留 fixed 对照。
- 先并行准备完整 IFEval／MATH-500 原生 Qwen 基线与真实训练语料，评测运行与训练测试按 GPU 分时安排。

## 数据与首轮训练入口

- 采用 HuggingFaceH4/no_robots 固定 revision `e6f9a4ac5c37faeb744ba9ecf0473184d7f8105b`，原 train 9500／test 500；CC-BY-NC-4.0，仅用于本轮研究稳定性诊断。来源文件 hash 入库，数据不入 git。
- 使用原生 non-thinking chat template，仅监督最后 assistant 回答；训练和开发按初始 prompt 去重，固定开发 pilot 32 条。packing 对切块边界显式重置位置、屏蔽第一个 target；过长／不支持样本计数，不静默截断为完整对话。
- 原始语料包含 Unicode 行分隔符，Python splitlines 会错误拆开合法 JSON 字符串。已改用 JSONL 的 LF 边界解析，并增加回归测试。
- 新训练入口支持 root FSDP2、重计算、精确 CE/KL、全局梯度裁剪、独立 router 学习率、开发集验证、DCP 与 HF 导出。小模型两卡训练／同进程 replay 已通过；数据解析代码更新后需重新冻结身份再验独立进程恢复。
- 完整 IFEval／MATH-500 正在 GPU 6／7 执行；IFEval 首次启动早于服务 ready 导致连接失败，确认 ready 后重启任务，没有计作有效评测。

## 第一轮验证与吞吐

- 两卡小模型完整恢复通过：独立新进程下一步 loss 与全部参数摘要一致；同流程开启真实 Inductor 也通过，捕获 2 个 graph。新增数据与日程测试通过。
- 真实语料冻结：训练 9484 条／2,784,719 input tokens／1,741,314 assistant targets；开发 500 条。排除重复 1 条、不满足末尾 non-thinking continuation 的 15 条，未超长；hash 和协议见 `corpus_tokens.json`。
- 四卡 4B、512-token fixed 首轮完成：热步约 3325–3971 input tokens/s、2120–2730 targets/s，峰值约 41.4 GiB／卡。包括冻结教师前向、精确 KL、重计算、FP32 master 和全局梯度裁剪；模型加载与保存不在该热步速度内。继续测试 2048 和 learned stress，不能以此推断 mixed 吞吐。
- LCB 数据覆盖审计发现：已固定的 test5 增量实际日期为 2024-09-22–2025-01-04，日期筛选后 164 条；它不是整个报告日期区间。官方 loader 的 release_v5 是 test.jsonl 到 test5.jsonl 的并集。旧 32 题分数保持有效子集回归语义，但不能当完整 v5／报告复现。证据见 `lcb_coverage_audit.json`，后续还需对齐报告采用的数据快照。

## 真实长度与先验敏感性决策

- 四卡 fixed 2048-token 热步约 11.3k–12.3k input tokens/s、7.4k–8.3k assistant targets/s，显存仍约 41.4 GiB／卡。采用 SDPA，包含教师和精确 KL；后续八卡需要独立测量，不直接乘二。
- 冻结开发 pilot 前四个 pack 的初始路由扫描：prior 4／3.5 时不偏离原层，CE≈3.973；prior 3.0 时偏离约 0.075%，CE≈4.017；2.5 时偏离约 1.51%、CE≈4.471；2.0 时偏离约 8.46%、CE≈8.172。由此选择短程开放日程 4→3，前 16 步保持，之后 112 步缓降；不直接降到 0。
- 首轮对照冻结为 128 步、2048 长度、相同训练 pack 顺序与 CE＋0.5 KL。fixed 与 learned 使用相同 1e-5 主体学习率、1e-4 router 学习率，warmup 8 步；用开发集判断稳定性，不用 benchmark 调参。
- 完整 IFEval 出现极长生成，eager 长上下文会触及默认 HTTP 10 分钟 timeout 并可能重试重复计算。已停止未完成轮次，设客户端 7200 秒且禁用自动重试，IFEval 原生 Qwen 改用 HF SDPA 后端重新执行；此前 4 条结果不混入新轮。MATH-500 原 eager 轮继续，最终报告分别注明 attention 实现，不能据此宣称两任务共享完全相同数值后端。

## mixed 成本与长生成调度

- prior=0 随机 learned 压力场景偏离约 97.3%，512 长度热步约 286 input tokens/s，相比 fixed 约慢 12.6 倍；2048 长度约 1.1k–1.2k input tokens/s，也显著慢于 fixed。此模型 CE/KL 很差，仅用于最坏分组负载诊断，不是质量候选。
- 已启动 128-step fixed／缓降 learned 的同 token 对照；每个完成后自动执行独立进程 DCP 恢复检查，随后核对 HF 重载。
- IFEval 中长生成造成微批完成等待。为避免只占一张卡却阻塞整套评测，改用 GPU 4／5 两个数值配置相同的 Qwen SDPA 副本，经 loopback least-busy 代理分发，元数据必须完全一致；仍由一个 EvalScope run 处理完整 541 条，不拆分或重写 scorer。旧未完成轮保留、不汇入最终报告。GPU 0–3 留给训练，GPU 7 继续数学评测。
