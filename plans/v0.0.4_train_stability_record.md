## 数据与首轮训练入口

- 采用 HuggingFaceH4/no_robots 固定 revision `e6f9a4ac5c37faeb744ba9ecf0473184d7f8105b`，原 train 9500／test 500；CC-BY-NC-4.0，仅用于本轮研究稳定性诊断。来源文件 hash 入库，数据不入 git。
- 使用原生 non-thinking chat template，仅监督最后 assistant 回答；训练和开发按初始 prompt 去重，固定开发 pilot 32 条。packing 对切块边界显式重置位置、屏蔽第一个 target；过长／不支持样本计数，不静默截断为完整对话。
- 原始语料包含 Unicode 行分隔符，Python splitlines 会错误拆开合法 JSON 字符串。已改用 JSONL 的 LF 边界解析，并增加回归测试。
- 新训练入口支持 root FSDP2、重计算、精确 CE/KL、全局梯度裁剪、独立 router 学习率、开发集验证、DCP 与 HF 导出。小模型两卡训练／同进程 replay 已通过；数据解析代码更新后需重新冻结身份再验独立进程恢复。
- 完整 IFEval／MATH-500 正在 GPU 6／7 执行；IFEval 首次启动早于服务 ready 导致连接失败，确认 ready 后重启任务，没有计作有效评测。

## mixed 成本与长生成调度

## 真实模型恢复失败与修复

- 首轮 fixed 128 步及 HF 导出成功，但 same-process replay 的参数 SHA 不一致：loss 完全相同，梯度范数 2.94446397 vs 2.94444060。该轮标为 `failed_exact_resume`，未运行后续 learned，也未伪记训练验收通过。
- 在真实 `[1,32,2048,128]` BF16 SDPA 上重复 backward，默认模式的 q 梯度不逐字节一致；开启 deterministic algorithms 后 q/k/v 均一致，证据 `sdpa_backward_determinism.json`。
- 新训练入口默认 `torch.use_deterministic_algorithms(True)`，固定 CUBLAS workspace、禁用 cuDNN benchmark 并启用 deterministic。两组 128 步都在新 `_deterministic` 目录重跑，不放宽 loss／参数完全一致标准。
- 同时修复多卡开发验证末尾重复计权：所有 rank 仍等次数 forward，超出开发 pack 数的 rank 屏蔽 targets 和路由统计，最终只计唯一 pack。旧曲线明确保留为重复加权的历史诊断。
- 完整 500 条独立开发集原始 CE≈3.514，首轮 fixed 导出约 2.020；后者仅为失败候选的质量观察，最终采用修复后重新导出的模型。

## 真实 4B 训练 compile 探针结果

- 4 卡、512 长度、LR=0 的 eager／Inductor 各 4 步均完成，编译捕获 2 个 graph，前向与反向都实际执行。排除首步后 3 步的热段加速约 1.163×。
