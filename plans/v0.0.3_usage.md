# v0.0.3 推理与评测复现

模型环境使用 `.venv-cached`（torch 2.10.0+cu130／Transformers 4.57.6）；评测使用独立 `.venv-eval`（Python 3.12／EvalScope 1.0.0）。精确安装清单见 `reports/v0.0.3/eval_environment.txt`。所有命令在仓库根目录运行，GPU 分配必须按当前授权调整。

## 推理

```bash
CUDA_VISIBLE_DEVICES=0 .venv-cached/bin/python scripts/infer.py \
  --model artifacts/bootstrap/rmt-bound-4b \
  --prompt '用一句话介绍 Transformer。' --prompt '17+25 等于多少？'

CUDA_VISIBLE_DEVICES=0 .venv-cached/bin/python -m rmt.inference.server \
  --model artifacts/bootstrap/rmt-bound-4b --name rmt --port 8901 --max-context 8192
```

默认 BF16／真实 Inductor 编译／recurrence capacity KV cache／non-thinking。`--eager` 选择严格参考计算路径，`--thinking` 为离线接口启用 thinking。Qwen 对照使用 `--backend qwen --eager --model /share/project/eai_pwm/models/Qwen/Qwen3-4B`。

服务只绑定 `127.0.0.1`，支持 `/health`、`/metadata`、`/v1/models`、非流式 `/v1/chat/completions` 与单 prompt `/v1/completions`。不支持 tools、logprobs、stream、`n>1`，会明确报错。服务有真实请求微批队列，默认 batch 4／等待 15ms；finished 行补 pad，不提前压缩 batch。presence penalty 作用于已生成 token，Qwen 与 RMT 使用同一采样实现。请求可通过 `chat_template_kwargs.enable_thinking` 显式选模式。

KV 按 recurrence 而非 expert 保存。容量缓存只用于推理，分配后追加写入，attention 仅读取有效前缀；cache mutation／动态长度 attention／路由调度在编译图外。固定路径编译 QKV 与 O／MLP 投影；混合路径保留数值敏感的 norm／QKV／residual eager，只编译 MLP。没有静默编译失败回退。随机 mixed 尚未获得相对同实现 eager 的 compile 加速，详见记录。

HF checkpoint 负责 config、权重、tokenizer；runner 使用本仓库的 RMT 类加载，避免旧导出目录的 Python 实现覆盖新推理逻辑。没有将 v0.0.2 DCP 训练恢复文件当作 HF 权重。

## 验证与性能

```bash
CUDA_VISIBLE_DEVICES='' .venv-cached/bin/python -m pytest -q
CUDA_VISIBLE_DEVICES=0 .venv-cached/bin/python -m rmt.inference.validate
CUDA_VISIBLE_DEVICES=0 .venv-cached/bin/python -m rmt.inference.benchmark --matrix
CUDA_VISIBLE_DEVICES=0 .venv-cached/bin/python -m rmt.inference.benchmark --mixed --profile
```

真实固定路径的严格参考只承诺已测输入逐字节相同；编译路径单独做误差／greedy／质量验收。`--matrix` 禁用 EOS、固定生成 32 token，报告三次热运行；首次编译调用可能复用磁盘 Inductor 缓存，不能称为完全冷机器编译。mixed 报告中的性能限制不会被标为固定路径验收通过。

## 评测

网络只从环境读取代理，不写入仓库。已有环境无需重装；首次创建可运行 `python scripts/setup_eval.py`，该环境依赖本机只读的系统 torch，不能视为任意机器通用 wheel 锁。

```bash
CUDA_VISIBLE_DEVICES='' PYTHONPATH=src .venv-eval/bin/python -m rmt.evaluation.prepare
CUDA_VISIBLE_DEVICES='' PYTHONPATH=src OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 \
  .venv-eval/bin/python scripts/probe_sandbox.py

# 占用指定八张卡，四个 RMT／四个 Qwen 单卡副本；Ctrl-C 只关闭本脚本的子进程。
.venv-eval/bin/python scripts/serve_replicas.py --gpus 0,1,2,3,4,5,6,7

# 另一个终端运行：
CUDA_VISIBLE_DEVICES='' PYTHONPATH=src OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 \
  .venv-eval/bin/python scripts/run_eval_phase.py \
  --rmt-ports 8901,8903,8905,8907 --qwen-ports 8902,8904,8906,8908
CUDA_VISIBLE_DEVICES='' PYTHONPATH=src .venv-eval/bin/python -m rmt.evaluation.summarize
```

也可用一个模型副本执行单任务：

```bash
CUDA_VISIBLE_DEVICES='' PYTHONPATH=src .venv-eval/bin/python -m rmt.evaluation.run \
  --model rmt --port 8901 --benchmark math_500 --phase representative
```

配置见 `configs/eval/quick_non_thinking.json`。每集 pilot 16 题／1024 token，正式快速回归 32 题／2048 token；seed 由 master seed 与最终 messages 派生，跨模型一致。Redux／C-Eval 固定四学科，数学覆盖五难度。没有自写评分器：adapter、prompt、提取、评分和聚合均来自 EvalScope。JSONL loader、HTTP seed／日志与代码执行隔离是本项目的薄层接入。

LCB 的 `test5.jsonl` 为固定 v5 增量，验证整个文件的上游 LFS SHA256 后按 2024-10-01 至 2025-02-28 过滤；没有下载全部历史 release_v5 拼接。Landlock＋seccomp 限制文件访问、写入、网络与进程创建，限制 CPU／内存／wall time；工具不存在或探针不通过时必须先处理基础设施错误。它是本机 Linux 的受限子进程方案，不是通用容器后端。

`reports/v0.0.3/dataset_manifest.json` 保存版本、源文件哈希及 sample selection。大型题目、原始 response、逐题评分、provenance、checkpoint 哈希位于 `artifacts/v0.0.3/`，汇总结果入库。审计要求完整题数、非空评分、无重复题和无基础设施异常；框架吞掉错误不能算作有效成绩。

自动结果目录 key 包含 checkpoint、协议、selection 和代码指纹。更换模型／模式会隔离缓存。已有结果重跑会使用 EvalScope 缓存；`scripts/verify_eval_resume.py WORK_DIR` 在服务重启后校验元数据一致，并强制要求零新模型调用、预测和评分文件不变。已知评分资源修复可通过 `scripts/rescore_eval.py WORK_DIR` 显式复用生成、重做评分，保留原 provenance 与修复记录。

## 范围

代表性快速回归不能等同于 Qwen3 报告复现，也不能用 32 题证明质量提升。完整清单和 deferred 原因见 `configs/eval/inventory.json`；论文长输出／多次采样配置见 `report_profiles.json`，未执行全量。thinking 本版仅做小样例通路检查；付费 judge、受限数据、工具交互和长上下文后续单独开展。
