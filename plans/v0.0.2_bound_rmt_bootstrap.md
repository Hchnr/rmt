# RMT v0.0.2：绑定专家最小实现与正确性验证

日期：2026-09-29。前置方案：[v0.0.1 总体大纲](v0.0.1_outline.md)。

本文是下一阶段的实现计划。本次仅编写计划、检查本地资产；尚未安装训练环境、实现模型或运行 GPU 训练。下文的代码结构、命令和验收结果文件都是拟实现的交付。

## 1. 推荐从哪里开始

**先完成“本地 Qwen3-4B → 36 套绑定专家 → 固定路径等价验证 → 学习路由短跑”的完整链路。** 对应总体大纲的 M1，并提前验证 M2 的关键技术组合。

先建立可以信任的模型和基线，再用 8×H100 做 24h 质量实验。首个最小交付是：同一批 token 输入原 Qwen 和固定路径 RMT，验证输出、loss 和关键中间结果一致。

本版完成后，应能回答：

1. 原 checkpoint 是否被完整、正确地搬进成套专家池？
2. token 选择不同专家时，attention、循环状态与梯度是否正确？
3. 模型能否以 HF 格式保存、重新加载、单条及批量生成？
4. router 能否从任务损失获得梯度并改变专家选择？
5. packing、compile、FSDP2、重计算能否在同一模型上组合执行短训练？

本版保持首轮约束：纯文本、`E=36` 套绑定专家、`R=36` 次循环，Q/K/V/O/gate/up/down 使用同一个专家选择。解除绑定、动态退出、更强教师、完整官方评测和高性能推理引擎接入按大纲后续安排。

## 3. 技术选择与环境准备

本版建议用 **原生 PyTorch + HF 自定义模型接口**。复用锁定版本的 Qwen3 norm、RoPE、tokenizer 与生成接口，自己实现成套路由、循环调度、attention 数据流和 cache。完整训练框架的接入放到模型接口稳定之后；本版提供薄层训练短跑入口和 FSDP2 探针，为后续评估 TorchTitan 提供依据。

环境实施顺序：

1. 创建项目隔离环境，建议 Python 3.11；依赖选择先尝试 `torch==2.7.1` 的 CUDA 12.6 wheel、`transformers==4.51.3`，其余依赖解析后锁定。这是待验证的初始组合，不是已通过测试的环境。
2. 先跑 CUDA BF16 matmul、SDPA forward/backward、`torch.compile` 实际编译、两卡 NCCL collective，再加载 4B。记录 Python、torch、CUDA runtime、Triton、Transformers 和驱动版本。
3. 驱动 535 需要关注 CUDA runtime 与编译路径的兼容性：CUDA 12.x 的最低驱动范围并不能保证所有 PTX／JIT 路径可用。若 compile 探针失败，定位后更换兼容的软件组合，记录最终锁文件；不把只通过 eager 当作 compile 可用。依据见 [PyTorch 安装版本表][torch-versions]和 [CUDA 兼容性文档][cuda-compat]。
4. 首先使用 PyTorch math attention／SDPA；FlashAttention、grouped GEMM 自定义 kernel 不作为开始实现的依赖。

原始模型目录作为读取来源，转换 checkpoint、训练产物与报告写到项目产物目录。加载本地基座时使用显式目录和 `local_files_only=True`，避免意外换用远端版本。

## 4. 模型接口与权重组织

### 4.1 配置与对象边界

拟实现 `RmtConfig`、`RmtForCausalLM`、单个 `RmtRecurrentCell`、`BoundExpertBank`、`BoundRouter` 和按循环深度索引的 cache。

| 配置 | 本版定义 |
| --- | --- |
| `model_type` | 独立的 RMT 类型，不伪装成原生 Qwen3 |
| `num_experts` | 从本地 `num_hidden_layers` 读取，4B 为 36 |
| `num_recurrences` | 4B 默认 36；与专家数分别保存 |
| `binding_mode` | `full_block`，七类投影绑定成套 |
| `router_top_k` | 建议首版固定 1 |
| `routing_mode` | `layer_order`、`forced`、`learned` |
| `norm_policy` | 两处 pre-norm 与 Q/K norm 随整套专家；final norm 共享 |
| `cache_layout_version` | 显式保存，cache 以 recurrence 为索引 |
| 其它 | 完整保留原 GQA、RoPE、词表、EOS、embedding/head 绑定等设置 |

`layer_order` 在第 r 次循环选专家 r，用于等价校验；`forced` 接受测试用的固定路由表，覆盖专家重复、跨 token 选择差异和未使用专家；`learned` 使用套级 router。真实 4B 配置与小模型测试共用实现，小模型不把 36 写死。

专家权重只注册一次，循环控制器重复访问同一个专家池。路由索引在 cell 入口产生，经过 attention 和 FFN 时保持不变。optimizer 不重复收集专家或绑定 head 的参数。

### 4.2 确定的转换映射

| 原 Qwen 权重 | RMT 对应项 |
| --- | --- |
| `model.layers.e.self_attn.{q,k,v,o}_proj` | 第 e 套 attention 投影 |
| `model.layers.e.mlp.{gate,up,down}_proj` | 第 e 套 FFN 投影 |
| `model.layers.e.{input,post_attention}_layernorm` | 第 e 套两处 pre-norm |
| `model.layers.e.self_attn.{q,k}_norm` | 第 e 套 Q/K norm |
| `model.embed_tokens`、`model.norm` | 共享 embedding、final norm |
| LM head | 重新绑定到 embedding，不补造另一份输出矩阵 |

逐分片读取和转换，记录每个源键的目标键、shape、dtype；源参数不得静默遗漏。新增 router／循环步参数单列，转换前后统计唯一参数，基座部分应仍为 4,022,468,096。

不要只把 `num_hidden_layers` 改成 1；HF 源模型中的层编号／cache 索引也不能直接当专家编号沿用。可参考锁定的 [Qwen3 源实现][qwen-source]核对运算顺序，attention 的 cache 索引由循环控制器传入。

## 5. 一个循环步如何执行

建议 token 级、top-1、成套路由。每个有效 token 在循环 r 选择 `e[i,r]`，完整 cell 的所有投影及套内 norm 使用同一 e。

一次循环的计算顺序：

1. 根据进入 cell 的表示和循环步选择专家；padding token 不进入路由统计／辅助损失。
2. 按专家分组，应用对应 input norm 和 Q/K/V 投影；执行对应 Q/K norm。
3. 把 Q/K/V 放回原 batch、样本和 token 顺序，按原 Qwen 顺序应用 RoPE。
4. 使用样本边界、padding、序列位置构造因果可见性，在完整合法历史上执行 GQA。
5. attention 输出按 token 对应的专家执行 O 投影，再加第一次残差。
6. 使用同一个专家的 post-attention norm、gate/up/down，完成第二次残差。
7. 得到本次循环输出，进入下一次循环；最终只经过一次共享 final norm 和 LM head。

**不能把分到同一专家的 token 当成一个独立序列调用完整 Qwen decoder layer。** 这会改变 attention 的历史可见性；分组只服务于参数选择与矩阵运算，attention 的序列关系必须恢复。

先实现便于校验的 gather/scatter 参考路径，可按专家循环执行非空 token 组；不得物化 `[token, in_dim, out_dim]` 的逐 token 权重副本。后续优化替换这一 dispatch 层，模型数学定义保持一致。

### 5.1 KV cache、位置与 packing

- cache 组织为每请求、每循环步的一组 K/V；历史 token 存其当时被选专家生成的 K/V，后来的专家切换不重算旧 K/V。
- 跨 token 选择不同专家时，Q/K 表示空间仍需学习兼容；成套绑定保持的是单个 token 内的参数配套关系。
- `position_ids` 表示样本内位置，`cache_position`／物理存储位置分别处理；循环编号不是 RoPE 位置。
- chunked prefill 和 decode 的 mask 明确考虑 past length；不能对非方形 Q/K 直接套用从左上角对齐的三角 mask。参照 [SDPA 定义][sdpa]验证实际可见性。
- packing 保存 `segment_ids`／边界信息，attention 只看同 segment 的历史；样本开头的 label 不连接前一条样本末尾。位置重置、loss mask 和教师输入使用相同边界。
- 小规模正确性验证可用显式 block-diagonal causal mask；正式高吞吐 varlen packing 属于下一阶段优化，避免把二次方 mask 宣称为生产级实现。
- 训练时关闭可变推理 cache，完整反传穿过所有循环；重计算不得修改持久 cache。推理先支持单条、静态变长 batch、cache 重排和 EOS 后样本剔除。

## 6. Router 的最小可训练方案【本版建议】

### 6.1 先把前向语义固定

一个共享 router 读取 cell 入口的 token 表示，使用 FP32 计算 score；加可配置的循环步先验，再 softmax。`argmax` 选一套专家，所有七类投影沿用该索引。循环步先验初始偏向原层，可按预定日程减弱；控制平局时的选择规则，记录路由 margin。

`layer_order` 绕过 router 及其门控，作为严格等价模式。`forced` 用于测试不同 token、循环重复调用同一个专家时的数据流和梯度累积。

### 6.2 显式验证 router 的任务梯度

建议首先评估“hard top-1 前向 + 选中概率的直通代理梯度”，以避免首版计算全部专家。设 `z` 是选定整套专家计算后的 cell 输出，`h` 是入口表示，`p_e` 是该 token 选中专家的概率：

`h_next = z + (p_e - stop_gradient(p_e)) * (z - h)`。

前向严格得到 z，反向给 router 一条通过残差变化量传播的任务梯度；attention／FFN 内部保持绑定定义。**这是有偏的梯度估计，不是 hard argmax 的精确导数，也不等价于计算所有专家的 soft mixture。** 在 config 和实验日志中明确标记，先通过小实验检验它是否能改变路由。

`p_e` 按 token 广播到 hidden 维度；零前向修正项回写时保持 z 的 dtype，避免 FP32 router 把整个循环 hidden state 提升为 FP32。固定路径验收不使用该修正项。

验收需要关闭 router 辅助损失，单独证明 CE 或非零 KL 能产生有限、非零 router 梯度并更新参数；另开辅助损失时分别记录各损失。不能只看到负载均衡 loss 下降就认定 router 学到了任务。

等价初始化时，纯教师 KL 可能接近零，因此梯度检查使用有任务信号的 CE 或受控非等价状态。直通代理的 backward 与 hard forward 的有限差分不一致是方法定义，测试应核对指定代理梯度，而非要求通过 hard argmax 的数值梯度检查。

如果短跑只有专家更新、router 长期保持原路径，先检查先验强度、饱和、代理梯度与任务信号。若该方案不可用，在本阶段调整并记录替代方案，再进入大训练。

## 7. 分层验证与通过条件

验证按“小模型正确性 → 真实 4B 等价 → 动态路由 → 组合训练”推进。以下阈值是实现前的初始标准；如需调整，必须记录原因和对照，不能仅为让失败通过而放宽。

| 验证 | 检查内容 | 通过条件 |
| --- | --- | --- |
| 参数迁移 | tensor、shape、dtype、绑定关系与唯一参数量 | 原参数无遗漏／重复；数值逐 tensor 相同，新增参数独立列账 |
| 小模型固定路径 | 同配置原 Qwen 与 RMT，FP32、关闭随机性、同 math attention | logits／hidden／loss 初始采用 `atol=1e-5, rtol=1e-4`；关键参数梯度另行逐项比较 |
| 真实 4B 固定路径 | 相同 token、position、mask、dtype、backend | 报告逐循环误差、logit max error／相对 RMSE、ΔNLL；BF16 初始要求相对 RMSE≤1e-3、ΔNLL≤1e-3；异常从首次偏离定位 |
| 成套路由正确性 | 人工指定不同 token 的专家、同专家跨循环重复 | 七类投影始终同索引；与慢速手工参考一致；重复调用梯度正确相加 |
| 因果性与 packing | 改未来 token／另一 packed segment，或改变 batch 同伴 | 已有合法 token 输出不随不可见内容变化；packed 与分开计算的有效 token loss／梯度一致 |
| Cache | 一次 forward、chunked prefill、逐 token decode | 同路由／同 kernel 的有效 token logits 在约定容差内一致；cache 按循环深度分离 |
| Batched generation | 不同长度、左右 padding 输入处理、EOS、cache 重排 | 与逐条执行一致；padding 不污染位置或专家统计 |
| 学习路由 | 任务梯度、参数更新、路由变化及专家负载 | 关闭辅助 loss 后 router 仍有任务梯度；可控短跑能改变选择，loss 无 NaN |
| HF 往返 | 导出、退出进程、从本地重新加载 | 配置、权重绑定、路由模式和 logits 一致，`generate` 可运行 |

生成序列相同只是补充证据，不能替代 logits 和因果性检查。greedy 用于受控工程回归；正式 thinking 评测另按技术报告协议，不能拿 greedy 回归结果作能力成绩。

验证固定路径梯度时绕过直通代理；`learned` 模式采用另一套代理梯度检查。路由临界点可能放大浮点差异，首先使用有明确 margin 的测试样例，再单独记录临界样例，区分数值误差与实现错误。

## 8. 训练短跑与效率兼容性探针

本版先实现薄层 CE + 冻结教师 KL 训练入口。小模型使用固定合成 token 与小型确定性样例；真实模型使用少量本地 tokenizer 编码的中英文／代码样例。它们用于 correctness 和 smoke，不用于声称质量收益。

KL 明确采用 `KL(p_teacher || p_student)`，按相同有效 token mask 归一化；teacher `eval()`、关闭梯度，温度与温度缩放因子显式配置。小模型完整 logits 作为基准，4B 按 token 分块计算 LM head／loss，检查分块与完整 loss／梯度一致。

| 探针 | 最小内容 |
| --- | --- |
| 单卡 eager | 小模型短跑，验证 optimizer、梯度累积、router 与专家更新 |
| 重计算 | 按循环段、优先 non-reentrant checkpoint；同路由／随机种子对照完整反传；不能 detach hidden state |
| Compile | 固定形状下真正编译投影／norm／MLP 等计算；记录被编译范围、dispatch graph break、重编译次数和编译耗时；不用 eager backend 冒充通过 |
| FSDP2 | 先两卡小模型，与同全局 batch 的单卡参考比较 loss、梯度／更新；测试各 rank 路由不同和局部未使用专家 |
| 四者组合 | 小模型启用 packing + compile + FSDP2 + 重计算，以实际混合路由训练至少 20 个 optimizer steps；检查 loss／梯度、专家统计与恢复 |
| 8 卡 4B | 使用 E=R=36、短序列做至少 5 个 optimizer steps 和保存恢复，记录峰值显存／有效吞吐；再做一组受控混合专家路由，避免只验证原层路径 |

FSDP2 先以整个共享 recurrent cell／专家池为稳定的通信边界，各 rank 执行一致调用顺序；不对“仅路由选中时才调用”的单个专家直接独立 wrap。比较循环区间保留 unsharded 权重与重复 reshard 的成本，记录共享参数跨循环使用和重计算能否正常反传。参照 [FSDP2 指南][fsdp2]及[重计算文档][checkpoint-doc]实现并实测。

动态分组的 Python 参考路径可能只适合 correctness。小模型上四项可组合、4B 短序列能训练，尚不意味着满足 24h 质量实验吞吐；本版要报告瓶颈和编译覆盖率。下一阶段据此决定 grouped GEMM、varlen attention、wrap 策略及训练框架接入。

训练恢复至少包含模型、optimizer、scheduler、RNG、router 先验日程、样本顺序／进度；与不中断训练比较恢复后的下一步。推理 HF 导出和完整训练恢复分别验收。

```bash
torchrun --standalone --nproc_per_node=8 -m rmt.smoke_train --config configs/bootstrap/qwen3_4b_integration.yaml
```

每次运行记录模型来源、环境锁定信息、seed、dtype、attention backend、E/R、路由模式、有效 token 数、误差／loss、时间与显存。报告明确区分 `passed`、`failed`、`not_run`；未执行的验证不写成已通过。

## 10. 实施顺序与完成定义

| 步骤 | 交付 | 后续依赖 |
| --- | --- | --- |
| B0：环境与资产 | 隔离环境、锁文件、GPU／编译探针、模型 manifest | 环境探针通过后开始模型运行 |
| B1：固定路径小模型 | config、成套专家池、循环 forward、显式 mask | FP32 forward／backward 等价后接真实权重 |
| B2：4B 转换与基线 | 本地 Qwen→RMT 转换、真实 BF16 等价报告、固定 fixtures | 不一致时先定位转换／算子问题 |
| B3：完整推理语义 | forced token 路由、KV cache、packing 正确性、HF 保存加载、batch generate | 避免仅原层路径通过而动态路径错误 |
| B4：学习路由短跑 | 任务梯度、套级选择变化、CE/KL 与恢复训练 | 确认模型可训练，再验证系统组合 |
| B5：组合与交接 | 两卡四项组合、8 卡 4B smoke、性能瓶颈报告 | 决定下一份训练效率与 24h 实验 plan |

本版完成需交付可重新加载的绑定专家 HF checkpoint、可复现命令、关键测试、分层验证报告和性能初测。checkpoint 属于已迁移／短跑模型，是否提升能力由后续实验判断。

进入 24h 正式实验前，还要另行确定：训练语料及规模、主质量指标与阈值、thinking 配比、完整训练框架与性能优化、教师生成成本、原 Qwen 继续训练对照和固定评测子集。模型转换、缓存或 router 仍有失败项时，不以延长训练代替修复。
