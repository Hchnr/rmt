# v0.0.4 阶段结果

状态：本轮训练链路、短程对照、完整原生基线和独占八卡吞吐验收均已完成。未获得路由质量收益；原一次未复现的 RuntimeError 和论文协议差距仍明确保留为限制。

## 已得到的结论

缓慢开放路由已经产生实际路径变化，短程训练没有崩塌，但本轮没有发现优于固定原层路径的质量证据。当前更适合先改进路由学习与执行效率，再扩大训练预算。

两组均从 Qwen3-4B 初始化，E=R=36，绑定整套投影和 norm；四卡、2048 长度、128 步，使用完全相同的 927,901 个有效输入 token 和 590,157 个 assistant targets。固定路径与开放路径的训练步耗时分别约 108.31／143.23 秒，后者为 1.3225 倍；这是同 token 对照，不是同 GPU-hours 对照，也不是 24h 效果实验。

开放日程：prior 从 4 开始保持 16 步，再用 112 步缓降至 3。FP32 master／BF16 计算、确定性 SDPA、FSDP2、重计算、精确 CE＋0.5×教师 KL；基础／router LR 为 1e-5／1e-4，AdamW weight decay 为 0。

## 全部 500 条开发样本

所有配置只计算一次 82 个唯一 pack、90,874 个监督 targets；CE 越低越好。

| 模型／执行路径 | CE |
| --- | ---: |
| 原始 Qwen 对应层路径 | 3.51414 |
| 固定路由训练后 | 2.02056 |
| 开放路由训练后 | 2.17900 |
| 同一开放权重，强制回原层路径 | 2.02464 |

同一权重回到原层路径后恢复到接近固定训练的水平，支持新增损失主要与路径改变有关。开发集含之前用于日程诊断的 32 条 pilot，独立于训练，但不是完全盲测的最终 test；英语 no_robots CE 下降不能直接解释为通用能力超过 Qwen。

开放模型的逐层选择偏离比例为 0.4474%，但至少一次改变路径的有效输入 token 占 14.30%，监督预测位置占 13.25%。不能把这两种比例混淆。最常见的是从 0 编号的 step 17→expert 12；转移计数只是描述，不构成逐题因果解释。

证据：[完整开发结果](holdout_opened.json)、[同权重路径消融](holdout_opened_layer_order.json)、[路由统计](trained_route_analysis.json)、[训练曲线](training_curves.svg)。

## 冻结 checkpoint 的能力回归

沿用 v0.0.3 固定 32 题、non-thinking、2048 输出上限；已核对题目、请求 seed 和生成配置相同。以下为逐题审计的精确比例（官方汇总会四舍五入）。

| 模型 | MATH 子集 | IFEval prompt strict |
| --- | ---: | ---: |
| 原始 Qwen | 27/32（84.375%） | 23/32（71.875%） |
| 固定路由训练后 | 28/32（87.500%） | 22/32（68.750%） |
| 开放路由训练后 | 27/32（84.375%） | 20/32（62.500%） |

开放模型的数学总分虽然与原模型相同，但两道题的得分改变；IFEval 有 11 道题得分改变，净减少 3 道通过。固定模型数学净增 1 道、IFEval 净减 1 道。样本很小，不构成提升或显著性结论；目前没有优先推广开放 checkpoint 的依据。

数学达到输出上限的比例：原模型 3/32，两种训练模型均为 1/32；IFEval 均为 0/32。候选在评测前冻结，未按 benchmark 选模型。详见 [配对结果与审计](trained_quality.json)。

## 可重复性与数值边界

- 两个真实 4B 候选都通过同进程和独立进程恢复检查：下一步 loss 和参数 SHA256 完全相同。小模型 eager／compile 同样通过。
- HF BF16 导出重载的 pilot CE 差分别约 0.000561／0.000354，小于明确门槛 0.005；这里是数值容差验收，不声称导出前后逐字节相同。
- 默认 SDPA backward 曾导致真实模型恢复时参数 SHA 不同；开启确定性算法后解决。旧失败候选保留且不纳入最终对照。
- 可选训练 compile 已在真实 4B 前向／反向执行。四卡 512 长度 LR=0 探针的三步热段加速约 1.163×，同批最大 CE 差约 0.01027、teacher KL 约 0.00072–0.00107（eager 为 0）。未建立编译训练质量等价，因此两组正式候选都保持 eager 投影。
- 30 项自动测试通过；真实模型恢复、HF 重载和当前训练源码身份核对见 [验证证据](verification.json)。

## 数据与适用范围

数据为 `HuggingFaceH4/no_robots` 固定 revision `e6f9a4ac5c37faeb744ba9ecf0473184d7f8105b`，CC-BY-NC-4.0，仅用于研究诊断。训练保留 9,484 条、开发 500 条；只监督最后 assistant 回答，屏蔽文档间和切块边界 targets，packing attention 隔离文档。训练语料总量仅约 278 万输入 token，不足以支撑有意义的 24h 持续训练配方。

## 完整 IFEval 基线与恢复边界

原生 Qwen HF SDPA 全部 541 条完成，435/541 prompt strict≈80.4067%（官方汇总 80.41%），技术报告为 81.2%，差约 -0.79pp；仅 1/541 因长度上限结束。这个结果比旧 32 题子集更有代表性，但仍不能称为论文 prompt／版本／RNG 的完全复现。

原一次双样本批次返回 RuntimeError；539 条缓存保留后，剩余两条在相同源码／模型／请求 seed／生成配置下恢复成功。随后额外复现原双样本批次也成功（1341 次 forward，108.34 秒），因此没有证据将原错误归因于确定的批量算法 bug；由于原服务未保存堆栈，根因仍未确定。服务已补充异常堆栈日志，此修改不改变生成算法。

相同 prompt／seed 在单样本和双样本执行时可以产生不同采样文本，不能将请求 seed 相同解读为任意 batching 下逐字节一致。完整评分不被额外诊断替换。详见 [恢复与诊断](ifeval_recovery.json)。

与 v0.0.3 原 32 题子集共享样本中，IFEval 有 4 条评分字典变化、数学有 3 条；后端、输出预算和实际 microbatch 均可能影响结果，不能将变化单独归因于某一项。这里只报告已有事实，没有按分数选择后端。

最终数学只采用完整 SDPA 新 run，之前 eager 未完成结果全部排除；IFEval 成功利用缓存恢复。数学最后完整调用约 3141 秒；IFEval 的 `run_summary.wall_seconds` 约 77 秒只代表最后缓存恢复调用，**不代表整个评测耗时**，原约 89 分钟的失败调用另见归档日志。完整证据见 [全量审计与协议](full_baseline.json)。

## 独占八卡吞吐与预算边界

所有组均为真实 4B、8×H100、FSDP2、确定性算法、SDPA、重计算、精确教师 KL，投影保持 eager。每组 4 步，仅后 3 步用于热段合计；下表 throughput 为全局八卡合计，显存为各 rank 的最大 allocated 峰值。

| 路由 | 长度 | 输入 tokens/s | targets/s | 热步峰值 GiB/卡 | 24h 热段输入 token 上限 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 固定原层 | 512 | 5,627 | 4,074 | 35.79 | 486.1M |
| 固定原层 | 2048 | 17,096 | 11,188 | 35.80 | 1,477.1M |
| 充分混合 prior=0 | 512 | 313 | 226 | 35.79 | 27.0M |
| 充分混合 prior=0 | 2048 | 1,368 | 896 | 35.80 | 118.2M |

四组包含加载与退出的外层累计约 554.9 秒（9.25 分钟）；完整阶段记录见 [编排归档](training_stages/20260929T141459.694902Z.json)。

2048 下充分混合比固定路径慢约 12.49 倍。压力配置逐层偏离约 97.15%，512 配置约 97.27%；不能把它们当作最终 prior=3、约 0.45% 偏离候选的实际速度，也不能按卡数线性外推旧四卡结果。

24h 数字仅为三步热段乘以 86400：不含 batch 搬运、zero_grad、路由统计、加载、验证、保存、数据变化和长期波动，**不是持续吞吐承诺**。显存列也不涵盖 checkpoint／HF 导出或整个进程的 reserved 峰值。当前约 278 万输入 token 的训练语料不足以支撑按这些上限直接重复 24h 的有效实验。

固定 2048 的热段上限约 14.77 亿输入 token、充分混合约 1.18 亿；是否有质量收益应先通过路由对照建立证据，再扩大数据和预算。历史四卡非确定性探针只作历史诊断，与这四组最终确定性测量区分保存。详见 [汇总 JSON](training_summary.json)。

## 建议的下一阶段

先保留固定路径 checkpoint 作为训练系统基线，针对路由质量做小规模、预先冻结的对照，暂不直接扩大到 24h 训练。当前 router 只有选中概率的有偏代理梯度；它没有显式比较替代专家的任务收益，而跨原始层的专家也未必能直接交换。下一轮可先在开发诊断集做固定权重的局部路径替换对照，测量替换前后的 CE／教师 KL，检查 router 分数是否真的排序了有用的选择，再决定路由监督或开放日程。

效率方面先保留正确性参考，评估分组 GEMM／减少 Python regroup 同步的收益。任何吞吐优化都要同时报告实际偏离路由比例，不能拿几乎完全固定的路径代表充分混合场景。更大语料、更强教师和同 GPU-hours 的质量比较应在路由具备正向证据后再扩展；本阶段不解绑七类投影、不引入动态退出。
